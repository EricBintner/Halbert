## 1. Core Philosophy: The Utility-First Embodiment

Halbert is not a chatbot that answers questions about computers, nor is it a traditional 17-page IT admin dashboard. 

Halbert **is the host computer itself**:
> *"An LLM that identifies as the computer itself is fundamentally more useful than an LLM that merely answers questions about computers."*

To ensure this vision delivers real-world leverage rather than decorative gimmicks, every capability in Halbert 2.0 must pass the **Utility Standard**:
* **Zero Decorative Fluff:** No artificial "breathing" animations, no abstract visual graph noise, and no forced biological jargon.
* **Radical Context Efficiency:** Never freeze the primary chat during heavy diagnostics; offload background audits to autonomous subagents.
* **Frictionless Shell Ergonomics:** Eliminate copy-pasting between terminal output and LLM prompts via inline streaming terminals, out-of-view accordion docking, and 1-click lasso diagnostics.
* **Safe, Reversible Agency:** Every configuration change is bounded by dry-run diffs, parametric headroom simulations, and an atomic 250ms rollback guarantee.

### Contradictions Resolved

1. **Session router complexity:** The orchestrator doc (§4) prescribes a 15ms affinity pass with ONNX embeddings + FTS5 + temporal decay on every prompt. The feasibility doc (§4) correctly says *"never run an LLM classifier on every keystroke"* and prescribes deterministic FTS5-only routing. **The feasibility doc is correct.** FTS5 alone handles 90% of cases; embeddings are deferred to the ambiguous-match tier only.

2. **250ms rollback guarantee:** Physically impossible to guarantee for arbitrary multi-file changes (e.g. systemd unit refactor + `daemon-reload`). Revised to **"best-effort rollback within 1-5 seconds for single-file changes; manual confirmation for multi-file."** The synthesis matrix above has been updated accordingly.

3. **Dream Cycle 03:00 scheduler:** Requires a scheduler that survives reboots and doesn't conflict with user cron. `scheduler/` exists but must be **opt-in, not default**.

### Refined Build Stages

| Stage | Goal | Effort | Unblocks |
|---|---|---|---|

| **2. Real PTY backend** | Replace `subprocess.run()` with async PTY + 1MB ring buffer + 60s idle reaper | ~90 lines in `terminal.py` | Streaming terminal UI (highest-leverage UX) |
| **3. SQLite session store + FTS5** | Migrate `ConversationStore` from JSON to SQLite with FTS5 on summaries. Skip embeddings. | ~120 lines | Zero-manual-session paradigm |
| **4. One real subagent** | Build `StorageAuditorAgent` only (not all 5). Runs `smartctl`/`zpool scrub` in isolated PTY, emits Somatic Block. | ~150 lines | Subagent pattern generalizes |
| **5. Living Reflexes** | Add `reflexes/` YAML store written by the Reflection block. Trigger matching via regex/telemetry signature in Tier 0. | New module | 1-click runbooks |
| **Deferred** | Parametric headroom sliders, "What Changed?" biographical diff, GSAP FLIP docking animation | — | Ship the dock first, animate later |
