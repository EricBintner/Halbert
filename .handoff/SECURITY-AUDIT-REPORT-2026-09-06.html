01 — Verdict

The capability is not the problem. The absence of a boundary around it is.

Halbert is built to hold more of a machine than an application normally does, and that is the product, not a defect. What the audit found is that almost none of that capability sits behind a door — and that the doors which exist mostly do not close.

Three findings carry the rest. About 315 of 334 HTTP routes have no authentication of any kind, including the one that spawns a PTY. The single authorization primitive in the tree, require_local_admin, is a loopback source-IP check — which every co-resident process already satisfies, and which a rebound browser tab satisfies too, because nothing validates the Host header. And the permission surface the user can actually see — the Tool Permissions tab — is consulted by exactly two tools, neither of which the agent's executor registers, and writes to a path the enforcement engine never reads.

That last one is the shape of the whole UI-and-control lens. The audit kept finding controls that are true in the interface and false in the process: a microphone master switch that writes a file and never stops the running pipeline; a Vision Autonomy card whose senses key is silently discarded by the endpoint that receives it; redaction that returns the unmodified frame on any host without the macOS Vision backend while still labelling the capture redacted. A control that lies is worse than a missing one, because the user stops looking.

On macOS the sensors cannot legally work at all as packaged. There are no NSUsageDescription strings, so TCC kills the process rather than prompting; entitlements and signingIdentity are both null, so an ad-hoc signature changes every build and no grant would persist anyway; and the capture code runs in a Python sidecar that resolves an interpreter out of a user-writable $HOME path. Meanwhile the app process holds a system-wide active CGEventTap that can read and delete any keystroke on the machine, alongside security.csp: null.

None of this needs a rewrite. It needs a boundary, applied by construction rather than by memory, and a consent model that records what was granted instead of storing a boolean. Both are designed below, and the work is sequenced into twenty rows.

02 — Threat model

Four actors, because breadth alone is not a finding.

Halbert is designed to be given the screen and the shell. So the test applied to every candidate finding was not "can it do something powerful" but: is this access gated by an explicit, informed, revocable owner decision, and is it reachable by anyone who is not the owner. There is no written threat model in the repository today; this is the one the audit ran against, and it should become documentation/legal/THREAT-MODEL.md.

03 — The twelve criticals

Each survived three independent verifiers trying to kill it.

Every finding below was checked by adversaries working three separate lenses — does the cited code actually say this, is the path reachable on a default install, and is this a defect rather than deliberately-granted product capability. Twenty-eight candidates did not survive and are not here. Two of the twelve are Windows-only and therefore unreachable today; they are included because the code ships now and the Windows target is still named.

01

Zero authentication on ~315 of 334 dashboard routes

CriticalT1 · local
halbert_core/halbert_core/dashboard/routes/terminal.py:247

Whatcreate_app() installs exactly one middleware — CORS — and all 40 include_router calls omit dependencies. The 24 auth dependencies that exist are confined to five federation files.

PathAny second process on the machine POSTs a command to /api/terminal/exec and gets a PTY under Halbert's uid — which by design holds Full Disk Access, camera, microphone and Screen Recording. The safety gate is a content filter, not an identity check, and only its BLOCKED tier stops anything.

02

No Host-header validation anywhere: DNS rebinding gives any website the whole API

CriticalT2 · network
halbert_core/halbert_core/dashboard/app.py:574

PathA page the owner visits rebinds its own hostname to 127.0.0.1. The browser now treats the attacker's origin as same-origin with the dashboard, so CORS is irrelevant and the page reads and writes every route. This is what turns "it's only bound to loopback" from a mitigation into a false sense of one.

03

PTY stdin is written with no auth and no safety gate after spawn

CriticalT1 · local
dashboard/routes/terminal.py:357 · routes/websocket.py:118

What_gate_command runs once, at spawn. Every subsequent write — over HTTP /input, over the WebSocket, or via /stage — goes straight into the live PTY ungated. The session list is readable unauthenticated, so a caller can find someone else's session and type into it.

04

Shipped deploy units bind the unauthenticated dashboard to 0.0.0.0

CriticalT2 · networkLinux
deploy/halbert-host.service:24 · deploy/halbert-home.service

WhatBoth units set HALBERT_HOST=0.0.0.0 and pass --host 0.0.0.0, with no hardening directives at all — no NoNewPrivileges, no ProtectSystem, no CapabilityBoundingSet. Arbitrary host file read and write, and a PTY, offered to the LAN. Nothing refuses a non-loopback bind without a token.

05

Arbitrary file write, escalating to root through a prefix-only allowlist

CriticalT1 · local
dashboard/routes/editor.py:379 · packaging/polkit/halbert-file-helper:31

WhatRoute validation is literally path.startswith('/'). The privileged helper it calls allowlists by unnormalized string prefix against /etc/, /usr/lib/systemd/, /var/lib/ and then runs cat > "$FILE_PATH" as root — so /etc/../root/.ssh/authorized_keys passes. The helper is resolved from the repo working tree on a source install, and falls back to plain sudo -n tee when pkexec is absent, which skips the allowlist entirely.

06

Any command the regex table does not recognise runs with no confirmation

CriticalT3 · injection
halbert_core/halbert_core/tools/safety.py:671

WhatThe classifier is a denylist whose default is MEDIUM, and only HIGH prompts the user. So one injected command the table has never seen executes silently. Adjacent: find … -exec <any program> is classified SAFE — "directory listing" — because the SAFE rule is a bare prefix match, which also means anything named ls*, dir*, find* or locate* clears every role cap.

07

The sensitive-path gate reads the raw argument; the handler expands the tilde

CriticalT3 · injection
halbert_core/halbert_core/tools/safety.py:681

Whatwrite_file(path="~/.ssh/authorized_keys") is MEDIUM and runs; the byte-identical call spelled /Users/you/.ssh/authorized_keys is HIGH and stops for confirmation. The gate depends on spelling. cwd is never classified at all, so rm grub.cfg with cwd=/boot is MEDIUM.

08

Home Assistant's confirm and forbid tiers are dead code

CriticalT4 · overstepHome Assistant
integrations/home_assistant/ha_governance.py:41

WhatLevels 2 and 3 key on domain names Home Assistant does not have. The garage-door tier and the forbidden tier never match anything, so the entries that were supposed to protect locks, alarms and valves protect nothing.

09

Unknown HA domain defaults to auto-execute

CriticalT3 · injectionHome Assistant
integrations/home_assistant/ha_governance.py:125

WhatThirteen device domains are classified; everything else returns Level 1 — act, log only. That set includes notify, shell_command, python_script and hassio. The one entity-level check that does exist is bypassed by putting the entity id in the data dict instead of the entity_id argument.

10

Wyoming audio ingress binds 0.0.0.0 with no token, and a bare transcript becomes an admin turn

CriticalT2 · network
halbert_core/halbert_core/audio/ingress/wyoming_ingress.py:128

WhatThe sibling agent transport refuses a non-loopback bind without WYOMING_TOKEN; the audio ingress does not. Anyone on the LAN writes one JSONL line and it is processed as an authenticated turn — because the dashboard voice path discards the biometric speaker role and runs every spoken turn as admin.

11 · 12

The command classifier is entirely POSIX — every Windows-native destructive command falls through

CriticalT3 · injectionWindows · not yet reachable
tools/safety.py:320 · dashboard/routes/terminal.py:133

WhatBoth safety tiers return SAFE or MEDIUM for Windows destructive and persistence commands, and streaming/sandbox.py returns the command unwrapped on any platform that is neither Linux nor Darwin. No Windows build exists, so nothing is exploitable today — but the permissive fallthrough is already written, and a Windows build would inherit it silently. This is the archetype of the pattern the audit calls permissive fallthrough, and it appears in at least four other places.

05 — One door

A single change closes thirty findings and reframes fifty-eight more.

Applying authentication and Host/Origin validation by construction to every listener — a default-deny router factory wrapping the 40 bare include_router calls, so a new route is authenticated by omission rather than by somebody remembering — closes 30 findings outright, including 5 of the 12 criticals and 17 of the 50 highs.

A further 58 findings name an unauthenticated route or a cross-origin page somewhere in their attack path. Authentication does not close those; most keep a same-uid local-process route. But it converts them from "any website the owner visits" to "a process already running as the owner", which is a materially different severity conversation.

The fail-open, in its own words

federation/peer_middleware.py:228 — the only authorization primitive in the product:

if not host:
    # No peer address at all … treat as local.
    return True

Verified not reachable through the shipped uvicorn TCP server — a real request always carries a client host — so this is filed low rather than dropped. It is one deployment change away from mattering, and the comment is the whole problem in three lines: the gate returns yes when it cannot tell.

Two rulings the matrix forces

Remove the CGEventTap. Its actual goal is stopping a bare Esc or Space falling through while the HUD is visible — not summoning it. RegisterEventHotKey plus overriding canBecomeKeyWindow achieves that completely, and neither requires any TCC grant. Halbert drops off the Accessibility list entirely, which is the row a journalist leads with.

Full Disk Access is in no profile. It has no API, no prompt and no per-folder revoke — and because PTY children are responsibility-attributed to Halbert, FDA is a whole-system grant for every command the agent runs. Per-folder TCC rows cost real capability and are worth it: each one is individually revocable in the Privacy pane.

07 — The three profiles

The line between them is one testable sentence: whether anyone asked.

A profile is a named set of proposals, not a runtime object. Accepting one writes N individual consent records, each stamped via: "profile:attentive". No code path anywhere asks "which profile am I" — the name is provenance, and every grant stays individually visible and individually revocable.

Reserved

I answer questions and read my own state. I don't watch, I don't listen, and nothing on this machine changes because of me.

Costs you: the job. It exists for evaluation, for a shared machine, and as the one-click floor on the review screen.
Preselected
Attentive

I look after this machine. I read its logs and its configuration, I change things when you approve the exact change, I look at your screen when you ask me to, and I hear you while you hold the talk button. I never watch on my own, and nothing leaves this computer.

Costs you: you have to ask. It won't spot the error on your screen by itself, won't answer to its name across the room, and doesn't know which of you is speaking.
Present

I'm awake in the room. I listen for my name, I keep an eye on the screen and the cameras you've set up, and I can act on the house. This is the setting where other people — guests, family, anyone who walks in — can be recorded. Choose it deliberately.

Costs you, in these words on the card: the privacy of this room, for you and for everyone else in it.

Attentive holds only capabilities that open inside a turn a person started, hold for that turn, and close with it. Present holds the loops that run when nobody is there. Every row below can be checked against that sentence, and it is the sentence to put in front of a journalist.

Five bright lines no profile crosses

  1. No profile grants egress. A profile is a statement about this machine's own body. It can never be the reason something left.
  2. No profile grants auto.act. Approval is never granted in bulk — act and orchestrate are individual typed-phrase grants with their own records.
  3. No profile grants a biometric. Voiceprint enrolment is always an individual act with its own disclosure and a 400-day default TTL. That is the whole GDPR Article 9 and BIPA answer, and it costs one line in the profile compiler.
  4. reach.privileged re-authenticates every time, including in Present. Today com.halbert.editor.policy sets auth_admin_keep on all three actions including write and exec; it belongs on the read-only diagnostic set alone.
  5. Neither Full Disk Access nor Accessibility is ever requested. Those are the two rows a reviewer reads first, and Halbert should simply not be on either list.

08 — First run

Seven screens, and nothing privileged starts before them.

Today onboarding is 373 lines — welcome, name, user type, scan, done. It names no capability, offers no decline, and every privileged subsystem has already started in the FastAPI startup event before the dialog can render. That last fact is why the fix is a two-phase boot, not a new dialog: Phase 0 reads the halt flag and the consent ledger and starts nothing else.

Screen 0 — What I already am

I'm the software this computer now runs. Not an app running on it — I speak as the machine you're sitting at. That makes me useful in a way an assistant isn't, and it means I'm asking for more than an app usually does.

Right now I can see: MacBook Pro · M3 Max · 64 GB · 2 TB, 61% free · up 4 days.

That's all of it. I have no eyes, no ears, and no permission to change anything.

It demonstrates the boundary instead of asserting it, before asking for anything. Not a modal — "Just look around" is a real decline that drops into conversation with no records committed. Where the OS reports more than one login-capable account it adds: "Other people use this computer. What you allow here applies to everyone who uses it." That sentence is a compliance artefact, and the account count goes into the consent record.

Screens 1–4 — Names, then how much should I notice

The machine asks what to call you and what it should answer to. Then the three profile cards, then the Reach roots — which directories, which displays. Screen 4 states plainly what Attentive leaves off, so the user knows what they are not getting. Screen 4b appears only when there is no local model, and routes straight into the per-destination egress decision rather than leaving a user with a machine that cannot answer.

Screen 5 — The review

Here is everything you're about to allow.

On my own, while you're away
· Read this machine's system logs and hardware sensors, continuously
· Read the configuration under /etc and keep dated copies, so I can tell you what changed
· Run a nightly check and write you a morning summary

When you ask me to
· Run a command in a terminal, under your user account
· Change a configuration file, after showing you the exact difference
· Take one picture of a display or a window, with passwords and keys blanked out first
· Hear you while you hold the talk button

One screen, the whole grant, nothing committed, every line carrying a Change link. This is the artefact an outside reviewer screenshots — and the one the user actually reads, because it is the only place the whole thing sits in one column.

OS permissions are requested at first use, never at setup. A wall of system dialogs during onboarding is a wall the user clicks through. Asking for the camera at the moment they ask the machine to look at something is the only time the request explains itself.

09 — Live controls

Stop, indicators, ledger, activity, export, destroy.

Stop everything

There is no such control today. autonomy/guardrails.py writes Path("data/safe_mode_active.flag") — CWD-relative, so a service started from / writes to /data/ or fails — shared between four unconnected enforcer instances, with no UI at all, and cleared by an endpoint that takes no auth and no body.

What replaces it is one action that writes <data_dir>/runtime/halt.json at mode 0600, atomically, flock-guarded, read in Phase 0 of boot before any subsystem starts — so surviving a restart is structural rather than a check somebody remembered. It halts every open grant mid-frame, the scheduler, tool execution, the agent's own PTY sessions, audio ingress, HA actuation at every tier, all egress, MCP dispatch and TTS mid-utterance. It leaves the user's own shells alone.

It does not halt the UI, the conversation, Settings, the activity log or export. The machine can still talk, so it can tell you it is stopped:

"I'm stopped. Nothing I do will take effect until you start me again — but ask me anything."

A machine that goes mute when halted is a machine people are afraid to halt.

Indicators that cannot drift

There is no live indicator for screen or webcam capture at all today, and the one audio indicator is driven by a config snapshot rather than the capture state — so it can say "off" while the microphone is open. In the new model every indicator renders from the set of open grants, naming the target rather than the class: "watching Display 2", not "screen capture on". The test is symmetric — for every open grant exactly one indicator row, and no indicator row without a grant.

The consent ledger

Consent today is a bare boolean in YAML. It records nothing about when it was granted, from which surface, by whom, or against what words — and nothing logs a flip. Every grant record in the new model carries the principal, the authentication, the surface, the channel, the build, the OS grant state, and text_shown_sha256: the digest of the exact words the person read. That last field is what lets you answer, two years later, what a specific user consented to in a specific release. Erasure writes its own ledger event before acting.

10 — The five gates

Falsifiable, each blocking every channel, ordered by what is bypassable without the one above it.

Gate 1

One door

require_owner on every mutating route, applied by a default-deny router factory so a new route is authenticated by omission. Host allowlist. Origin checks on all four WebSocket handlers. The _is_local_client fail-open inverted. A non-loopback bind that refuses without a token.

Prooftests/test_route_auth_census.py fails CI when any route lacks an auth dependency; an integration test drives curl and a simulated rebound origin at three routes and gets 403 from all three.

Gate 2

Nothing captures, executes or egresses without a lease

Every capture, exec and egress primitive takes a Lease positionally; the constructor is module-private and the only mint is require(). Redaction fails closed on the capability, so a host with no working backend cannot open a redaction-required lease at all.

ProofA deny-all canary boots with an empty ledger, drives every tool, route and startup path, and records zero captures, zero subprocesses, zero outbound sockets. A permissive-fallthrough lint closes the sandbox, config, discovery and redaction fallthroughs in one rule.

Gate 3

Stop works, survives a kill, and is visible

One action halting capture, scheduler and execution together, reachable from tray, every page, voice-at-ingress, hotkey, CLI and an HA switch. Resume requires an owner with OS re-auth.

ProofA test SIGKILLs the process mid-capture and asserts that on restart nothing perceives and the halt banner renders.

Gate 4

Consent resolves to specific words in a specific release

A capability with no record is denied. Every capability has committed copy; shipped digests match. granted: true is refused unless the principal is an owner on an authenticated surface.

ProofA test attempts a widening as the agent, as a peer, as MCP and as an unauthenticated loopback caller, and gets four refusals.

Gate 5

The agent cannot rewrite its own permissions, and the published documents are true

No governed path is writable by the agent through any write primitive. Skills load only from the manifest, only on a digest match. THREAT-MODEL.md exists.

Prooftests/test_agent_cannot_touch_itself.py — every registered tool × every governed path × every write primitive — and tests/test_security_md_claims.py, which pins each published claim to an assertion. Everyone rewrites the security document once; only the test keeps it true.

Plus one release gate for macOS: Developer ID signature, hardened runtime, notarized and stapled, usage strings present, sidecar frozen inside the bundle, CGEventTap gone, CSP set, updater configured. Until every one of those is true, every macOS sensor row reads "can't tell — this build isn't signed", never "on".

11 — The plan

Twenty rows, and a hard sequencing rule.

SEC-1 → SEC-2/3/4 → SEC-5 + SEC-8 → SEC-7 → SEC-6 ship as one train and nothing else lands first. No channel work, no signing work, no release notes. SEC-8 is inside that set deliberately — the three things a user can see must arrive with the three that make them true, or nobody can check the design.

12 — Your calls

Twelve decisions, each with the default the work will assume if no answer comes.

These are written in the shape of the DECISIONS.md "Open — founder calls" section. Four matter most, and one is a hard block.

IdQuestionDefault assumed
SEC-D1Does the App Store channel ship at all? The sandbox forbids Screen Recording, the PTY, /etc writes and a privileged helper.Ship it as the companion — the profile's subject is the paired body, not this Mac. 13 — Corrections owed

The published security policy makes claims the code contradicts.

At a "defensible to an outside reviewer" bar this is its own finding, and it is the cheapest one to fix. documentation/legal/SECURITY.md currently states:

Published claimWhat the code does
"Default policy requires approval for: service restarts, configuration file modifications, scheduled task creation, file deletions"config/policy.yml ships default_allow: true with write_config and schedule_cron both explicitly allowed, and the loader returns default-allow on any exception.
"Dashboard — Localhost only — Bound to 127.0.0.1"True of the default, but HALBERT_HOST and --host override it with no guard, and the two shipped deploy/*.service units set 0.0.0.0.
"All data stays local — No external API calls"Web search sends query text to third-party public SearXNG instances; cloud model slots send prompt and retrieved context; /api/rag/trending sends a fingerprint of the host's toolchain to api.github.com with no capability check.
"Audit logging — All operations are logged with context"run_command is outside the ledger entirely, and audit-log erase destroys records while verify_audit() still reports "No tampering detected".

The full list, including PRIVACY.md, is section D of the plan. The durable fix is tests/test_security_md_claims.py, which pins each published claim to an assertion — everyone rewrites the security document once, but only a test keeps it true.
