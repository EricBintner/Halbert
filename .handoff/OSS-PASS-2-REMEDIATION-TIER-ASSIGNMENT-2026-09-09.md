# OSS-pass-2 remediation — model tier / effort assignment and checklist

Written 2026-09-09. Source: `.handoff/oss-pass-2/remediation_plan.md` §4 (fifteen packets R-01…R-15). This is the tiering pass requested in chat: assign each packet a model tier (fable / opus / sonnet) and an effort level (ultracode / max / xhigh / high / med), execute only the sonnet-tier subset now, and track the whole set as a checklist.

## Tiering axes used

- **Model**: `opus` for anything security-critical, high-blast-radius, or holding many invariants across phases at once; `sonnet` for file-disjoint, deterministic, no-founder-decision-blocking work; `fable` did not fit any full packet (it would fit narrow copy/wording sub-tasks like the six SKILL.md description trims inside R-11 — flagged inline, not tiered separately).
- **Effort**: `ultracode` where the plan's own dispatch order says a packet can run in a parallel worktree alongside others (candidate for multi-agent fan-out); `max`/`xhigh`/`high`/`med` otherwise, by phase count, file breadth, and whether the fix needs new engineering (e.g. a real-corruption SQLite fixture) vs. pattern-following.
- A packet lands on **sonnet** only if: no outstanding founder-decision gate gates its ungated phases, it doesn't touch a file another in-flight packet owns, and its invariants are mechanical/deterministic rather than requiring judgment calls about security posture.
