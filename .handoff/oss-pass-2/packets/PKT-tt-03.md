## 1. Packet

**TT-03** — Command normalization/deobfuscation + fail-closed parsing.

## 2. User problem

The command safety classifier in `halbert_core/halbert_core/tools/safety.py` pattern-matches the raw command string exactly as the model emitted it, so trivially obfuscated destructive commands walk straight past the gate. The verifier confirmed live bypasses on the agent's primary command surface: `rm -rf ~/Documents` classifies HIGH (requires confirmation), but `r\m -rf ~/Documents`, `rm${IFS}-rf${IFS}~/Documents`, and `$(echo rm) -rf ~/Documents` all classify MEDIUM — allowed, no confirmation. Three compounding defects: (1) no normalization/de-obfuscation step exists anywhere before `BLOCKED_PATTERNS`/`RULES` regex the raw string (`_classify_command`, safety.py:845); (2) fail-open parsing — `ToolSafetyFramework._shell_segments` (safety.py:771) returns None for unparseable lines (unbalanced quotes, `$(...)` or backtick substitution), but that None only suppresses the SAFE tier via `_every_segment_is_safe`; CRITICAL/HIGH/MEDIUM rules still regex the raw unsegmentable string, so an unsegmentable command lands on MEDIUM "Unrecognized command pattern" and executes after a generic confirmation; (3) no founder-authored deny floor — `BLOCKED_COMMANDS`/`BLOCKED_PATTERNS` (safety.py:244-258) are hardcoded, so there is no config line the human wrote that outranks every bypass (role gate, confirmed=True, SAFE rules). Separately, the confirmation gate has no unattended-origin policy: `ToolExecutor.execute` (executor.py:673-682) returns `requires_confirmation=True` unconditionally for HIGH, and `AgentStateMachine._handle_awaiting_confirmation` (state_machine.py:5333-5343) is a no-op that waits forever with no timeout and no origin check — a HIGH-risk tool call from a scheduler tick, an MCP-originated turn, or a voice turn with no dashboard open pins the session in AWAITING_CONFIRMATION indefinitely. And there is no self-repo worktree-mutation rule: the founder runs concurrent sessions in this checkout, so an agent-initiated `git reset --hard` / `git checkout --` inside the Halbert repo destroys another session's uncommitted work. This is packet TT-03, verdict ACCEPT (FINAL-CRITICAL-DISCOVERY-BACKLOG-2026-09-11.md: "Command normalization/deobfuscation, fail-closed parsing, deny-list precedence, unattended-origin policy, worktree mutation rule"), deep-eval IDs HM07-M4, HM06-M1, HM06-M3, HM06-M2, HM06-M5, HM06-C2.

## 3. What to build

Lane C owns `tools/safety.py` + `tools/executor.py`. Build five things, all deterministic — never a model where a template suffices:

1. **Command normalizer (HM07-M4)** — a new module-level function in safety.py, e.g. `_normalize_command(command: str) -> str`, run at the top of `_classify_command` (and consumed by `_shell_segments`/`_every_segment_is_safe` via the normalized form), before any pattern match. Steps, in order: (a) strip ANSI escape sequences and NUL/control chars using the shared text-hygiene module `security/text_hygiene.py` (Wave-0 primitive from the backlog, dependency of this packet — build it there or consume it if TT-01 landed it first; do not fork a second stripper); (b) Unicode NFKC fold so fullwidth/homoglyph characters collapse to ASCII; (c) collapse backslash-newline continuations and remove backslash-escapes inside unquoted words (`r\m` → `rm`); (d) expand `${IFS}` and `$IFS` to a space; (e) fold `$HOME` and `~` via `os.path.expanduser` so `~/Documents` and `$HOME/Documents` classify identically; (f) iterate to the command starts — run the existing `_command_segments`/`_shell_segments` logic on the normalized string and classify each segment, taking the maximum risk. The classifier's `BLOCKED_PATTERNS`, `BLOCKED_COMMANDS`, `RULES`, and `_command_reads_secret` all then match against the normalized string, never the raw one. Log both forms on a BLOCK (raw + normalized) so the audit trail shows what the model actually emitted.

2. **Fail-closed parsing (HM06-M1)** — when `_shell_segments` returns None (unbalanced quotes, command substitution `$(...)` or backticks whose contents the classifier cannot see), the command must not fall through to "Unrecognized command pattern" MEDIUM. Change `_classify_command` so an unparseable line returns HIGH with `requires_confirmation=True` and a reason like "Command could not be parsed safely" — or CRITICAL/blocked when the unparseable construct is a substitution. No tier below HIGH may be reached by a command the parser declined to segment.

3. **Founder-authored deny list with precedence (HM06-M3)** — load a human-written deny file (one pattern per line, substring or regex, comments with `#`) from the Halbert config dir resolved via `utils/platform.py` `get_config_dir()` (same lazy-guarded pattern as `_platform_sensitive_dirs`, safety.py:202 — a missing file is an empty list, never a crash on import). Check it FIRST in `_classify_command`, before `BLOCKED_COMMANDS`, before the secret-read check, before every rule: a founder deny entry returns CRITICAL, `allowed=False`, and is unreachable by `confirmed=True`, RoleGate loosening, or any SAFE rule. This is the floor below every other decision. Founder decision gate: exact file path/name — propose `<config_dir>/deny_commands.conf` and flag it for ratification in the packet PR.

4. **Unattended-origin approval policy (HM06-M2)** — in `ToolExecutor.execute` at the HIGH-risk branch (executor.py:673-682), read the turn's origin from the already-bound `current_turn_channel` ContextVar (`agents/channels.py`: dashboard / voice / terminal registry) and the scheduler/MCP provenance signals (scheduler-submitted turns and `_provenance_of(tool_name)` == "mcp" for MCP-originated calls, executor.py:66). Policy: scheduler-origin and MCP-origin HIGH calls deny outright (return a blocked ExecutionResult with a first-person reason — "I won't run that without you here" — never naming a model); voice/dashboard/terminal-origin calls ask with a bounded wait (propose 10 minutes, deny-on-timeout). Wire the bound into `_handle_awaiting_confirmation` (state_machine.py:5333) so a pending confirmation older than the bound auto-denies and unblocks the state machine instead of pinning the session. Founder decision gates: per-origin defaults and the wait length — surface both in the PR.

5. **Self-repo worktree-mutation rule (HM06-C2)** — a classifier rule (normalized, per-segment) that classifies `git reset --hard`, `git checkout --`, `git clean -f`, and `git stash` (any form, including `git -C <path>` variants) as HIGH when the target path resolves inside the Halbert checkout, because concurrent sessions hold uncommitted work there. Resolve the repo root once via `git rev-parse --show-toplevel` semantics with the existing `_normalise_path`/`_within_path` helpers (safety.py:166/188); refuse silently failing the resolution — unresolved stays HIGH.

Also HM06-M5 (combined approval): when two independent detectors fire on the same call (e.g. secret-read + HIGH rule, or founder-deny-adjacent + SENSITIVE_PATHS elevation), emit ONE confirmation message that names both reasons, so the human sees the full basis in a single ask — build the reason-merging in `get_confirmation_message` (safety.py:961).

## 4. What NOT to build

TT-03 consumes its strip step; if it does not exist yet, build exactly the strip (ANSI/NUL/control chars) there as part of this packet's dependency and nothing more.
- Do NOT touch the RoleGate (`tools/role_gate.py`) or the R-08 permission lattice (ask axis, approvals, leases, halt) — the unattended-origin policy reads origin facts and the existing `requires_confirmation`/`confirm_action` machinery; it does not rebuild the approval infrastructure.
- Do NOT change `agents/state_machine.py` beyond the bounded-wait timeout in `_handle_awaiting_confirmation` and its call path — the AWAITING_CONFIRMATION state itself, `confirm_action`, and the event stream shape stay as they are.
- Do NOT add an LLM-assisted or "smart" deobfuscation pass — the normalizer is a fixed deterministic pipeline; no model anywhere in the classify path (standing rule: never a model where a template suffices).
- Do NOT gate on `is_local_model()` or any model property — this is command safety, orthogonal to model locality.
- Do NOT add new BLOCKED_PATTERNS for every obfuscation variant individually (that is whack-a-mole; normalization is the fix), and do NOT broaden `BLOCKED_COMMANDS` beyond the founder deny file.
- No migrations, no back-compat shims for the deny file — missing file = empty list (no-users rule).
- Do NOT surface any of this on a user-visible surface with new UI; the confirmation message text changes only, first person as the computer, no emoji, no model names.

## 8. UX rationale

Almost entirely invisible — this work lives behind the existing confirmation gate. The only user-facing surface is the confirmation/denial message text, which must obey the standing rules: the system speaks as the computer itself in first person, grounded in the measured fact (the matched rule, the actual command), never as an assistant, never naming an AI model, no emoji. Concretely: (1) a denied unattended call says something like "I won't run that without you here — it came in from the scheduler and needs your confirmation" (first person, origin named plainly); (2) a fail-closed parse says "I can't tell what that command does, so I'm not running it without your confirmation" — honest about the parser's limit rather than a generic risk label; (3) a founder-deny hit says the human blocked it: "You've asked me to never run this" — the deny list is presented as the owner's own standing order, not Halbert's judgment; (4) the combined approval (HM06-M5) lists every fired reason in one ask ("This reads a credential and modifies a sensitive path") so the human confirms with full information once, instead of sequential nags. When a timeout denies a pending confirmation, the conversation continues in the one seamless thread with a short first-person line that the ask expired — no modal, no conversation list, nothing staged-but-executed: commands remain staged, and a denied command simply never runs. Dashboard rendering of these messages uses existing TaskCard/confirmation components and shared-tokens colours — no new UI is built in this packet.

## 9. Acceptance criteria

1. **Normalizer closes the verifier's bypasses**: `r\m -rf ~/Documents`, `rm${IFS}-rf${IFS}~/Documents`, and `$(echo rm) -rf ~/Documents` all classify at least HIGH with `requires_confirmation=True` (the substitution form CRITICAL/blocked per the fail-closed rule), while `rm -rf ~/Documents` keeps its current HIGH verdict and benign chains (`ls && pwd`, `echo "a|b"`) keep SAFE/LOW — no regression on `test_safety_chained_commands.py`. 2. **Fail-closed parsing**: any command for which `_shell_segments` returns None (unbalanced quotes, `$(...)`, backticks) classifies HIGH-or-blocked, never MEDIUM "Unrecognized command pattern". 3. **Deny-list precedence**: a pattern in the founder deny file returns CRITICAL/`allowed=False` even when a SAFE rule matches, even with `confirmed=True`, even for an owner-role turn; missing file = empty list and the module still imports. 4. **Unattended-origin policy**: a HIGH tool call from a scheduler-origin or MCP-origin turn returns a denied ExecutionResult immediately (no AWAITING_CONFIRMATION pin); a voice/dashboard-origin HIGH call enters AWAITING_CONFIRMATION and auto-denies after the configured bound (default 10 min) with the session unblocked — verified by driving `_handle_awaiting_confirmation` past the deadline in a test. 5. **Worktree rule**: `git reset --hard` and `git clean -fd` targeting a path inside the Halbert checkout classify HIGH; the same command targeting `/tmp` keeps its prior classification. 6. **Combined approval**: when two detectors fire, one confirmation message names both reasons. 7. No new hard dependencies (Haloysius two-dependency contract untouched); no emoji, no model names, first-person copy in every new string.
