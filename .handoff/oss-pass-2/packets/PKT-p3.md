## 2. User problem

Halbert's halt semantics have a hole at the legacy approval engine. R-08 (merged) built the real halt axis in the permission lattice: `persona/permission/halt.py` gives `HaltState` with a persisted `<data_dir>/runtime/halt.json` (`PersistedHalt`), token-gated asymmetric resume (`mint_resume_token` / `resume`), and fail-closed boot (`load()` halts with `CONSENT_UNREADABLE` when the file cannot be read); `persona/permission/lease.py:464-472` honours it — a halted lease denies with `REASON_HALTED` on `AXIS_HALT` and trips the loop's stop event. But `approval/engine.py` — the approval store actually used by three live surfaces (`dashboard/routes/approvals.py:67-326`, `mcp/server.py:481,541`, `dashboard/routes/findings.py:57-65`) — has zero halt awareness. The word "halt" appears nowhere in its 419 lines. On a machine the owner has Stopped (or that halted itself on `GUARDRAIL_TRIPS`, `REDACTION_UNAVAILABLE`, a broken consent chain, or an unreadable persisted halt), the engine will still: accept and persist a new request (`request_approval` at engine.py:134-199, `queue_request` at :304-315), list pending requests as actionable (`get_pending_requests` at :317-333 filters on `status == 'pending'` only), return a stored request (`get_request` at :335-350), and — worst — record a fresh decision against a pending request while the machine is stopped (`_save_decision` at :395-402, reachable from `routes/approvals.py:235,324`). The lattice says a halted machine denies every capability regardless of the other four axes; the approval plane contradicts it, so an approver answering during a Stop gets an approval the lattice would refuse — two authorities disagreeing about the same machine state. The founder frame: Halbert speaks as the computer itself and "Stop everything" must mean everything; an approval engine that keeps trading while halted is a lie about measured machine state. This packet is the RESHAPE'd P3 per FINAL-CRITICAL-DISCOVERY-BACKLOG-2026-09-11.md line 122 ("P3 | RESHAPE | Lease/halt semantics — keep the halt, drop the broad lease registry") and the dispatch index line 186 (Lane I, merge 3/3, after SURFACE-01a expiry enforcement and P2 artefact binding land in the same file).

## 3. What to build

One file: `halbert_core/halbert_core/approval/engine.py`. Wire the existing halt axis into the approval engine so a halted machine's approval plane fails closed, in first person and deterministically — no new registry, no new store.

1. Constructor seam: `ApprovalEngine.__init__` gains an optional keyword `halt: Optional[HaltState] = None` (import `HaltState`, `PersistedHalt`, `HaltReason` from `..persona.permission.halt`). When `halt is None`, build one backed by the same on-disk state the lattice reads: resolve the data dir exactly as `consent/store.py` and the existing `HaltState(persisted=...)` call sites do (the persisted path is `<data_dir>/runtime/halt.json` per `halt.py:47-49` `HALT_FILENAME`/`HALT_SUBDIR` and `PersistedHalt.__init__` at :86), construct `HaltState(persisted=PersistedHalt(data_dir=...))`, and call `.load()` on it so an engine created after a Stop sees the persisted halt (fail-closed on unreadable, matching `halt.py:212-244`). Callers (`routes/approvals.py`, `mcp/server.py`, `routes/findings.py`) need no signature change — the default path is self-contained; tests inject a bare `HaltState()`.

2. Fail-closed gate, one helper: add `_check_halted(self)` returning the halt's `(reason_code, halted_by, halted_surface, halted_at)` when `self._halt.is_halted()` else `None`. Apply it at every mutation and every read that presents a request as actionable:
   - `request_approval` (:134): if halted, do not persist, do not prompt; return an `ApprovalDecision(approved=False, reason=f"the machine is stopped ({reason_code}, recorded {halted_at}); nothing is approved until it is resumed", decided_by='system')` and mark the request `status = 'rejected'` in memory only (no `_save_request` — a stopped machine records no new pending work; the decision itself is still written to history via `_save_decision` so the refusal is accountable, consistent with `HaltReason.AUDIT_UNWRITABLE`'s "an action that cannot be accounted for is not performed" — the refusal IS accounted for).
   - `queue_request` (:304): if halted, log and return without saving (the request never enters the pending set — queuing work onto a stopped machine is how stale approvals get answered after resume).
   - `get_pending_requests` (:317) and `get_request` (:335): if halted, return `[]` / `None` and log once — a stopped machine presents nothing as awaiting decision (read paths fail closed; the files stay on disk untouched per the no-delete directive).
   - Decision paths: the engine's own decision recording happens inside `request_approval`, but `routes/approvals.py:235,324` construct `ApprovalDecision` externally and save through the engine — add a public guard method the routes can call (or expose `is_halted()`), and inside `_save_decision` (:395) refuse to write a decision whose request is not already final when the machine is halted: raise `PermissionError` with the same first-person wording pattern as `halt.py:283-287` ("a resume needs a token minted for this halt...") so a route gets a 403-shaped failure, not a silent write. Keep the refusal deterministic — no model anywhere in this path.

3. No schema change to `ApprovalRequest`/`ApprovalDecision` beyond using the existing `reason` string; `ApprovalStatus.EXPIRED` handling stays SURFACE-01a's, hash binding stays P2's — P3 must not re-open those (rebase onto their merged engine.py; lane order I/3-of-3 per the dispatch index). On a successful resume (halt cleared), pending requests persisted before the halt reappear naturally in `get_pending_requests` — no tombstone, no migration, per "leave superseded data on disk, unread."

Tests: add `halbert_core/tests/test_approval_engine_halt.py` next to the existing `tests/persona/test_halt_persistence.py`: (a) fresh engine + injected `HaltState()` not halted → `request_approval`/`queue_request`/`get_pending_requests` behave exactly as today (regression guard against the baseline); (b) injected halted state → `request_approval` returns `approved=False` with `reason` containing the reason code, writes no request file under `requests/`, writes exactly one history record; (c) halted → `queue_request` writes no file; (d) halted → `get_pending_requests` returns `[]` and `get_request` returns `None` even with a pending file present; (e) `_save_decision` raises `PermissionError` while halted; (f) after `resume(token=...)` with a token from `mint_resume_token()`, `get_pending_requests` again returns the pre-halt pending file (resume restores visibility without any engine-side state); (g) engine constructed with `halt=None` against a `tmp_path` data dir containing a written `halt.json` (reuse `PersistedHalt` to write it) boots seeing the halt.

## 8. UX rationale

This is a correctness-of-voice fix on the one seamless conversation surface: the machine speaks first person grounded in measured state, and "Stop everything" (§4.1) is the strongest sentence it can say. After P3, that sentence is true at the approval plane: while stopped, the Approvals page and the MCP approval tools show nothing pending and can record nothing new — the UI's existing empty state does the talking, no new copy, no new surface, no emoji. The refusal text the engine returns (`the machine is stopped (<reason_code>, recorded <halted_at>); nothing is approved until it is resumed`) is first-person machine speech naming measured facts (the reason code and timestamp already persisted in `halt.json`), consistent with the lattice's own denial detail at lease.py:472. Nothing is deleted and nothing is silently dropped: a request refused during the halt leaves exactly one accountable history record, and requests queued before the Stop reappear on resume untouched — recoverable by construction, which is the trust property the founder's "watched, staged, never executed" posture depends on. No colours, no components, no settings change; the only user-visible delta is that a stopped machine stops answering.

## 9. Acceptance criteria

1. `ApprovalEngine` accepts an optional `halt: Optional[HaltState]` keyword; with `halt=None` it constructs `HaltState(persisted=PersistedHalt(data_dir=<the data dir halt.py uses>))` and calls `.load()`. 2. With a halted state: `request_approval` returns `approved=False` whose `reason` names the halt `reason_code`, writes no file under `<storage>/requests/`, and appends exactly one decision record under `<storage>/history/`; `queue_request` persists nothing; `get_pending_requests()` returns `[]` and `get_request(id)` returns `None` even when a pending request file exists on disk; `_save_decision` raises `PermissionError`. 3. With no halt (or after a token-authorised `resume`), all five operations behave byte-identically to pre-P3 main — no pending file is modified, moved, or deleted by the halt or the resume. 4. No other file is modified: `git diff --stat` shows `approval/engine.py` plus the new test file only. 5. No model is consulted anywhere in the new path; the refusal wording is a deterministic format string. 6. Existing engine consumers (`routes/approvals.py`, `mcp/server.py`, `routes/findings.py`) require no edits and their current tests behave as before (modulo the known-red baseline).
