## 1. Packet

**MP-3** — Idle-gap stream timeout + abort hook.

## 2. User problem

The streaming and non-streaming LLM call paths in Halbert use a single total wall-clock timeout that is wrong in both directions. In `halbert_core/halbert_core/agents/llm_client.py` every aiohttp call site builds `aiohttp.ClientTimeout(total=self.timeout)` with `self.timeout` defaulting to 120: line 149 (`OllamaClient.chat` first POST), line 165 (the no-tools retry POST), line 225 (`OllamaClient.stream` POST — inside the streaming path, so a healthy stream still emitting tokens is killed at 120 s), line 385 (`AnthropicClient.chat`), and line 438 (`AnthropicClient.stream`). A reasoning-class local model that thinks for three minutes before its first token, or a long generation that streams steadily past 120 s, is aborted mid-stream by the total budget even though the transport is healthy. In `halbert_core/halbert_core/model/client.py` the synchronous `requests` adapters (`_call_ollama` at :757, `_call_anthropic` at :668, and the OpenAI-compatible and peer adapters reached through `_do_llm_call` at :1253) pass a bare `timeout=timeout` to `requests.post`, which is a connect+read total with no abort channel at all. Second defect: there is no abort hook from the turn machinery to the HTTP layer. R-01 built turn-level stop/steer/redirect verbs claimed through `agents/turn_activity.py::TurnActivity` (stamp/claim, generation-guarded, single-shot), but nothing closes the in-flight aiohttp response or requests call when a stop lands — after `/stop`, the model keeps generating until the total timeout fires, up to 120 s of billable compute on a peer or cloud slot, and up to 300 s on the synchronous planning path. Third: retries sit in uninterruptible sleeps (MP-2's `tier_router.py:736` bare `time.sleep(wait)` blocks `/stop` for up to 60 s; that call site is shared scope with MP-2 C8). The correct shape, per the Hermes reference (`agent/chat_completion_helpers.py:586-613`), is an idle-gap detector: `ClientTimeout(sock_read=idle_gap, total=None)` so a stream that goes quiet for the gap dies while a stream that keeps producing lives, plus an abort hook that closes the aiohttp response/session from a foreign thread (shutdown, not close), claimed through the same `TurnActivity` generation mechanism so a late abort declines instead of killing the next turn's request.

## 3. What to build

Lane B hot file: `agents/llm_client.py` is shared with MEM-P6 — rebase on the current main-tree version before editing and keep the diff scoped to the timeout/abort seams. Build four items in priority order. (1) C7 idle-gap stream timeout (S): in `agents/llm_client.py` replace all five `aiohttp.ClientTimeout(total=self.timeout)` sites (:149, :165, :225, :385, :438) with a helper `_stream_timeout(model, num_ctx) -> aiohttp.ClientTimeout` that returns `ClientTimeout(total=None, sock_read=gap, connect=30)` where `gap` scales with context size (e.g. base 60 s, +15 s per 8192 tokens of num_ctx from `model/client.py::num_ctx_for_model`) and applies a floor (e.g. 300 s) when `utils/reasoning.py::is_reasoning_model` (:97) returns True for the slot's capabilities — capability-detected, never a name table. Keep the non-streaming `chat()` paths on a bounded total via the same helper with `total=None` replaced by a generous computed ceiling (gap x 10) so a hung non-stream call still dies. In `model/client.py` the synchronous `requests` adapters cannot idle-gap with `requests`; give `_call_ollama` (:757), `_call_anthropic` (:668), `_call_openai_compatible`, and `_call_peer` a `(connect, read)` timeout tuple with the read leg set to the same computed gap so the sync path gets the same liveness semantics. (2) M3 abort hook (M): add an `AbortHandle` to `agents/llm_client.py` — a thread-safe object holding the live `aiohttp.ClientResponse` (and session) for the in-flight request; the streaming methods register their response on it before iterating and clear it in `finally`. The abort closure calls `response.close()` plus `session.detach()`/connector shutdown from the calling (foreign) thread without awaiting. Wire the hook in `agents/state_machine.py` at the point where R-01's stop verb runs: the stop path calls `turn_activity.claim(gen, abort_fn)` so a stop that lands after the turn finalized declines (returns None) instead of closing the next turn's socket. The synchronous `model/client.py` path gets a coarser hook: a `threading.Event` checked between read chunks is not available with `requests`, so register the live `requests.Response` and call `response.close()` from the abort thread — verify against the CPython `requests`/`urllib3` close-from-other-thread behaviour and document the measured outcome. (3) M1 consecutive-stale streak gate (S): in `OllamaClient.stream`, count consecutive reads that arrive but carry no new content (empty keep-alive lines); after N stale reads (default 3), close the stream and raise a typed `StaleStreamError` rather than waiting for the next sock_read window, so a wedged-but-open connection fails fast into the retry taxonomy MP-2's C6 defines. (4) M5 leak-safe cross-thread scheduler (S): one helper `schedule_on_loop(loop, coro) -> concurrent.futures.Future` in `agents/llm_client.py` (or `utils/`) wrapping `asyncio.run_coroutine_threadsafe` with a done-callback that retrieves exceptions so a fire-and-forget abort scheduled onto the dashboard loop can never leak 'exception was never retrieved' warnings; the abort hook uses it whenever the abort originates off the owning loop. Reuse R-09-era primitives where they exist; do not build a second activity clock — `TurnActivity` is the claim mechanism.

## 4. What NOT to build

Do not touch the retry/backoff policy itself — the Retry-After taxonomy, `blocked_until`, BackendIdentity, and the interruptible `time.sleep` replacement in `halbert_core/halbert_core/agents/tier_router.py:736` belong to MP-2 (C6/C7/C8); MP-3 only makes the stream-level liveness and abort seams, and where both packets need the same two call sites in `llm_client.py` and `tier_router.py`, MP-2 owns the tier_router half. Do not change `num_ctx` computation, context-window probing, or the `_NUM_CTX_CACHE` high-water logic in `model/client.py:769-1225` — that is MP-4 scope; MP-3 only *reads* `num_ctx_for_model`'s result to scale the gap. Do not build a model-name-based timeout table (the standing rule: never key behaviour on model names; the reasoning floor must come from `is_reasoning_model()` capability detection at `utils/reasoning.py:97-130`). Do not add a second cancellation/activity registry — the claim goes through the existing `agents/turn_activity.py::TurnActivity` that R-01 uses; no parallel generation counter. Do not build per-request metrics, cost accounting, or usage rows (MP-4 theme I). Do not convert the synchronous `requests` adapters to aiohttp — the sync transport in `model/client.py` is deliberate (see the `_call_anthropic` docstring at :644-651 about running inside an already-running loop); MP-3 tunes its timeouts in place. Do not add UI surfaces, notices, or settings toggles; the slot/locality reroute notice is MP-2/MP-1-residual scope. Do not write migrations or back-compat shims for the timeout constructor signature — no users yet; update the call sites directly.

## 7. Effort

**M** — M overall, decomposed as S+M+S+S per the accepted deep-eval estimate. C7 (idle-gap timeout) is S: one helper plus five call-site edits in `llm_client.py` and four `requests` timeout tuples in `client.py`, all mechanical. M3 (abort hook) is the M core: it crosses three files (`llm_client.py` for the handle and registration, `model/client.py` for the sync response close, `agents/state_machine.py` for the claim wiring at R-01's stop edge), it is a cross-thread close whose correctness depends on generation-guarding through `TurnActivity`, and the `requests.Response.close()`-from-foreign-thread behaviour must be verified empirically rather than assumed. M1 (stale-streak gate) is S: a counter in one loop plus one exception type. M5 (leak-safe scheduler) is S: one helper wrapping `run_coroutine_threadsafe` with an exception-retrieving done-callback. The tier is opus not because of volume but because the abort hook's failure modes are subtle: a close that races turn finalize kills the next turn's request, and a mis-scoped edit in this lane-B hot file collides with MEM-P6. Dependencies justify sequencing: `activity_clock` (TurnActivity stamp/claim surface) must exist first — it does, merged in R-01 — and MP-2 must land first or concurrently so the `StaleStreamError` and idle-gap expiry have the typed error taxonomy (MP-2 C6) to raise into rather than inventing a parallel vocabulary.

## 8. UX rationale

No new UI and no new copy. The user-visible effects are behavioural: (1) a long reasoning turn on a local slot no longer dies at 120 s mid-thought — the stream lives as long as tokens keep arriving, so the first-person measured voice gets to finish what it started; (2) pressing stop during a generation actually stops the meter — the in-flight request is closed within about half a second instead of the daemon grinding on for up to 120 s on the async path or 300 s on the sync planning path, which matters on a peer or `:cloud` slot where that tail is billable; (3) a wedged connection whose socket stays open but stops producing tokens fails fast (stale streak) and surfaces through the existing error path as an honest transport failure rather than a silent two-minute hang; (4) a `/stop` issued while a retry backoff is waiting returns promptly instead of after the sleep (the tier_router half of that is MP-2's to land; MP-3's stream side must not reintroduce an uninterruptible wait). Any surface text that arises from these failures flows through the existing fallback/notice machinery MP-2 builds — the reroute/failure notice names the connection slot and locality, never the model (standing rule: never name or recommend an AI model on any user-facing surface), speaks as the computer in first person grounded in the measured gap ('the connection went quiet for 60 seconds'), and no commands are executed as a side effect — anything staged stays staged. No emoji, no new colours, no conversation-list affordances; this packet is invisible except through things that used to break no longer breaking.

## 9. Acceptance criteria

1. `grep -n "ClientTimeout" halbert_core/halbert_core/agents/llm_client.py` shows no remaining `total=self.timeout` on the streaming paths: `OllamaClient.stream` and `AnthropicClient.stream` build timeouts via the new helper with `total=None` and a nonzero `sock_read`; the two `chat()` paths use the computed ceiling, not the bare 120 default. 2. The gap is capability-driven: the helper consults `num_ctx_for_model` output and `is_reasoning_model()` and contains no model-name string matching (verified by reading the helper; `is_reasoning_model` at `utils/reasoning.py:97` is the only reasoning judge). 3. An `AbortHandle` (or equivalently named) object exists in `agents/llm_client.py`; both stream methods register their live response on entry and clear it in `finally`; the abort closure performs a non-awaiting close safe to call from a foreign thread. 4. The abort is generation-guarded: the stop edge in `agents/state_machine.py` invokes it through `turn_activity.claim(gen, ...)`, so a late abort returns None and cannot close a subsequent turn's request (visible in the diff at the stop-verb call site R-01 added). 5. `model/client.py` sync adapters pass `(connect, read)` tuples to `requests.post` with the read leg derived from the same gap computation; no adapter still passes a bare scalar `timeout=timeout`. 6. `StaleStreamError` (typed) is raised after the configured consecutive stale-read streak in `OllamaClient.stream` and maps into MP-2's error taxonomy rather than a bare `asyncio.TimeoutError`. 7. The cross-thread scheduling helper routes every off-loop abort through `asyncio.run_coroutine_threadsafe` with an exception-retrieving done-callback. 8. All pre-existing behaviours are preserved: the no-tools retry at `llm_client.py:151-177` still sets `tools_supported` exactly as before, and `chat()`'s `num_ctx` payload construction is unchanged.

## 10. Verification (measured state, not model judgment)

(a) New unit tests in `halbert_core/tests/` (add `test_llm_client_idle_gap.py`): a fake aiohttp transport that emits one chunk every 0.05 s for 3 simulated minutes completes without timeout under the new config (asserts total=None semantics — the stream outlives the old 120 s budget); a fake transport that goes silent after the first chunk raises within ~the configured gap (assert sock_read fires); a transport emitting empty keep-alive lines only raises `StaleStreamError` after exactly N reads. (b) Abort-hook test: start `OllamaClient.stream` against a slow fake server, call the abort closure from a second thread mid-stream, assert the generator exits within 1.0 s (measure with `time.monotonic()` deltas in the test, assert < 1.0 s) and that a second `claim()` with a stale generation returns None without closing anything (assert the next turn's fake response object is untouched). ## 11. Exclusions

Excluded from this packet with explicit destinations: (1) The interruptible backoff sleep in `agents/tier_router.py:736` and the whole Retry-After/error-taxonomy/`blocked_until`/BackendIdentity work — to MP-2 (C6/C7/C8), which the deep-eval names as the same-commit partner for the shared call sites; MP-3 lands after or alongside MP-2 and raises `StaleStreamError`/idle-gap expiry into MP-2's taxonomy, never a parallel one. (2) The slot/locality reroute notice text ('this turn ran on a cloud connection') — to MP-2's fallback transition notice work (OC03-C9 / OC14-C22 residual from MP-1's reshape). (3) Usage-anchored token accounting, context-cache route-keying, LM Studio loaded-state, `keep_alive` policy, prompt-prefix caching — all MP-4. (4) Prose-encoded tool-call repair and iteration-budget refunds — MP-5. (5) A general wall-clock 'maximum turn duration' ceiling — dropped per the deep-eval's minimum-viable scope: the idle-gap detector plus the abort hook covers the liveness and cancellation cases; a separate hard ceiling was not in the accepted proposal. (6) Converting `model/client.py`'s sync `requests` adapters to aiohttp — dropped per the `_call_anthropic` docstring rationale (:644-651); the sync transport is load-bearing and stays. (7) Any M5b tail items: none generated — the four items (C7, M3, M1, M5-scheduler) are the full accepted scope; nothing was cut to a tail because the deep-eval's minimum-viable version explicitly includes all four ('the idle-gap stream timeout (C7, S) and the interruptible backoff (C8, S — shared with MP-2) are the two highest-leverage items. The abort hook (M3, M) is the second priority. The streak gate (M1, S) and the leak-safe scheduler (M5, S) are third priority. All touch llm_client.py and client.py'). The only shared item, C8's tier_router half, is carried by MP-2 as stated in (1).
