## 1. Packet

**SCHED-P4** — Turn liveness (activity-clock).

## 2. User problem

Halbert has exactly one seamless conversation, and that conversation is serialized through a single asyncio turn lock in agents/state_machine.py. Two measured defects and one architectural gap remain around that lock's liveness story. First, the turn-liveness watchdog that R-01/A07-G10 landed on main (state_machine.py:2172 `_turn_watchdog`, fed by `_touch_activity` at :2160, with `TURN_STALL_SECONDS = 900.0` at :282 and `STALL_POLL_SECONDS = 5.0` at :284, clock state `last_activity`/`last_activity_note`/`touch()`/`idle_seconds()` on TurnContext in agents/states.py:338-348) has no test coverage anywhere in halbert_core/tests — a wedged turn aborting the one conversation, or the watchdog double-firing into a later turn, would be invisible until an operator noticed Halbert stopped responding. Second, the tool-execution heartbeat (HM01-C3) is only half true: stamps happen at tool start (:4148), tool output (:4193), tool completion (:4216), and stream chunks (:4779/:4791), so a long-running tool that produces no output between start and completion — a silent `run_command` building for twenty minutes — stamps nothing and the watchdog aborts live, productive work. Third, the activity clock the turn uses is a per-context field pair, not the shared `utils/activity_clock.py` primitive (dependency packet PKT-activity-clock, contract `record_activity(source)` / `idle_seconds()` / `is_stalled(idle_timeout)`, thread-safe, `time.monotonic()`) that MP-2, MP-3, SCHED-P2, DAEMON-01b, and TT-05 also consume — without migrating the turn clock onto it, five units grow five private clocks and "stalled" and "working" disagree per subsystem, which the code comment at state_machine.py:2164 already names as the failure mode. The operator-visible symptom this unit kills: Halbert silently stops answering (wedged holder pins the lock behind a 'waiting' badge, recoverable only by process restart — the exact scenario the TURN_LOCK_TIMEOUT_S comment at :253-261 describes for waiters, which nothing addressed for holders) — or, after this unit, a turn that is measurably alive (tool running, bytes flowing) is never aborted while one that has said and done nothing for the ceiling is ended cleanly through the lifted `request_stop`, with a receipt naming the abort.

## 3. What to build

In `halbert_core/halbert_core/agents/state_machine.py` (the only target file; Lane A, merge after MP-5 and before TT-05), plus the dependency's module it consumes:

1. Migrate the turn liveness clock onto the shared primitive. Replace the `last_activity`/`last_activity_note`/`touch()`/`idle_seconds()` pair on TurnContext (agents/states.py:338-348 is NOT a target file — consume, don't edit it: keep those four members as thin delegating shims to an `ActivityClock` instance so the other readers of `ctx.idle_seconds()` keep working, or hold the `ActivityClock` on the state machine beside `self.turn_activity` (state_machine.py:381) and have `_touch_activity` write to it). The clock instance is per-turn: created (or `reset()`) where `self._turn_generation = self.turn_activity.stamp()` runs at process() entry (:603), so one conversation's lock carries one clock per turn, and `live` vs `wedged` is exactly `clock.is_stalled(TURN_STALL_SECONDS)`.

2. Close the heartbeat gap (HM01-C3). The tool-execution path must stamp the clock at least once per STALL interval while a tool runs, not only at start/output/completion. In the tool-dispatch region around :4148-4216, wrap the tool await in a periodic stamp task (same shape as `_model_call`'s STOP_POLL_SECONDS slicing at :2207: await the tool coroutine in slices of `STALL_POLL_SECONDS`, calling `_touch_activity(f"tool running: {tool_name}")` between slices) so a silent long tool keeps the turn measurably live. Cancel the stamp task in a finally when the tool returns, raises, or the turn is stopped.

3. Test the watchdog that already exists (this is the bulk of the unit's value). Add tests (new file `halbert_core/tests/test_state_machine_turn_liveness.py`, modelled on test_state_machine_turn_lock.py's instance-level constant overrides at :461/:548): (a) wedged holder — a turn whose model call never returns and produces no events is aborted after `TURN_STALL_SECONDS` (override to ~0.2s) and `STALL_POLL_SECONDS` (override to ~0.05s); assert the turn ends, the lock is released, and a subsequent message starts a new turn; (b) live holder — a turn whose tool keeps the clock stamped past the ceiling is NOT aborted (assert process completes normally with the watchdog running); (c) generation discipline — a watchdog that wakes after its turn already ended cannot abort the next turn under the same session id (the `turn_activity.claim(generation, _abort)` single-shot at :2204 must no-op on a stale generation); (d) AWAITING_CONFIRMATION exemption — a turn parked on a confirmation past the ceiling is left alone (the early return at :2189); (e) abort goes through the cancel path (`_flag_cancelled` at :2202), not a silent kill, and the abort is logged with session, idle seconds, and last activity note.

4. Route the ceiling through the named constant only. Do not hardcode 900/1800 anywhere new; the founder-decision-4 recommended default is 1800s idle (30 minutes, Hermes's value) — changing the `TURN_STALL_SECONDS` default from 900 to 1800 is a one-line edit gated on that decision; build the unit so either value passes all tests (tests override the constant per-instance and never assert on the default's numeric value). Do not record the decision in DECISIONS.md from this session — it stays a founder gate, non-blocking per the registry.

No new colours, no UI surface, no emoji, no model names: the only user-facing effect is that Halbert answers instead of hanging, and the log line naming the abort.

## 8. UX rationale

The one-seamless-conversation surface lives or dies on this unit: there is no conversation list to escape to, so a wedged turn is a wedged Halbert. Today, if a model call hangs silently while holding the turn lock, every later message queues behind a 'waiting' badge that never changes and the only recovery is restarting the process — the operator experiences this as the computer going mute mid-conversation, the worst trust failure a first-person steward can have. After this unit, the computer recovers on its own: a turn that has said and done nothing for the ceiling is ended through the same `request_stop`-derived cancel path a typed /stop uses (no silent subprocess kills, per the standing directive and founder decision 4's recommended shape), the lock frees, and the next message just works — with an ERROR log line naming the session, the idle seconds, and the last activity note so the operator (or a doctor/findings surface later) can see what happened. Equally important is the negative: a turn doing real work — a twenty-minute silent build, a long model think — is never interrupted, because the heartbeat stamps make 'alive' a measured fact rather than an assumption; aborting productive work would teach the operator that long answers are unsafe, which is worse than the wedge. Nothing new appears on any surface: no badge, no banner, no settings toggle, no model names, no emoji, no colours. The system simply stops having a failure mode where it silently never answers, consistent with 'the system speaks as the computer itself, grounded in measured data' — here the measured data is the monotonic activity clock, and the speech act is the conversation continuing.
