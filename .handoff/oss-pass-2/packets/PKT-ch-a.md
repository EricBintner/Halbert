## 1. Packet

**CH-A** — Turn cause axis + envelope sanitizer + watcher starvation fix.

## 2. User problem

Halbert's talk door has no honest way to admit a machine-originated turn. Today `agents/channels.py` registers exactly three human ingress channels (DASHBOARD_CHANNEL, VOICE_CHANNEL, TERMINAL_CHANNEL) and `resolve_channel()` raises `ChannelRefused` for anything else — so a scheduler-fired task, a cognition tick, or a tool-event wake must either be refused outright or lie and claim the dashboard channel, which would also mis-stamp its speaker claim as ASSERTED via `CHANNEL_CLAIM_STAMP["dashboard"] = "dashboard_token"` (a credential the turn never presented). That is the structural blocker for master-plan item 03-C (prompted heartbeat) and for any scheduler-submitted turn; the deep-eval verdict is "cheap now, expensive after the scheduler starts faking a modality." Three companion defects ride the same unit: (1) there is no deterministic sanitization of the inbound envelope text at admission — channel-supplied metadata can reach prompt assembly carrying control-tag/unicode-tag content that today is only stripped downstream in two divergent sanitizers (`mcp/metadata.py:strip_unicode_tags` and `prompts/agent_prompts.py:_CONTROL_TAG_RE`); (2) a stop is not durable across process restart: input queued before a stop can be answered by a fresh process because there is no persisted abort-cutoff watermark; (3) `config/watcher.py:281-288` (and the twin at 328-336) is a live starvation bug — `create_sourceprep_reindex_callback` and `create_detector_trigger_callback` each cancel and re-create a `threading.Timer` on every file change with no floor deadline, so a continuously-changing config file defers the re-index/detector sweep forever. Reference shape: OpenClaw `src/auto-reply/templating.ts:310` (`InternalTurnSource?: "heartbeat" | "cron" | "exec"` — "Internal wake cause, independent of transport, transcript provenance, and execution authority") and `src/auto-reply/internal-turn-source.ts:24` (`normalizeInternalTurnContext` folds legacy source labels at ingress; runtime channels describe transport only). Halbert's vocabulary per the registry note is scheduler / tick / tool-event.

## 3. What to build

In `halbert_core/halbert_core/agents/channels.py`: (1) Add a closed `InternalTurnSource` enum (values: `SCHEDULER`, `TICK`, `TOOL_EVENT`) plus an `INTERNAL_CHANNEL = ChannelDeclaration(id="internal", claim_ceiling=ClaimStrength.UNVERIFIED, default_role="system", busy_verbs=frozenset({"stop"}), delivery=frozenset({"sse"}), transcribe_before_command=False)` registered in `CHANNEL_REGISTRY`. The ceiling is deliberately UNVERIFIED and there is deliberately NO entry in `CHANNEL_CLAIM_STAMP` for "internal" — a machine-originated turn carries no speaker claim at all; update `stamped_claim_source()` to return `None` for the internal channel regardless of what the wire declared (log a `claim_dropped` info line if a source was declared). (2) Extend `resolve_channel()` with a keyword-only `internal_source: Optional[InternalTurnSource] = None` parameter: when provided, return `CHANNEL_REGISTRY["internal"]` and ignore the modality string; when absent, behavior is byte-identical to today (the 04-A1 regression pin stands — absent fields keep current behavior exactly). Mutually exclusive with a human modality: passing both `internal_source` and a non-empty modality raises `ChannelRefused`. Carry the cause on the turn by adding an `internal_source: Optional[InternalTurnSource]` field read alongside the channel — keep it a separate small frozen dataclass `TurnCause(channel, internal_source)` returned by a new `resolve_turn_cause()` so CMD-A's authorization axis and MP-2's exit-reason axis can later compose into one `TurnContext` type (backlog §3.10) without a second constructed type drifting. Do not build TurnContext itself. (3) Envelope sanitizer: add `sanitize_inbound_envelope(text: str) -> str` in channels.py that imports the fold/strip primitives from `security/text_hygiene.py` (the unit's declared dependency — if text_hygiene has not landed yet, import `strip_unicode_tags` from `mcp/metadata.py` behind a single helper so the swap is one line later) and wraps every admitted turn's user text in the deterministic bracketed envelope (`[user_message]` ... `[/user_message]` style markers, matching the existing `[steered]`/`[/steered]` convention in `agents/steering.py:39-40`) after stripping control/unicode tags. Apply it at the one admission point in `agents/state_machine.py:process()` (around line 632 where `resolve_channel` is already called) so route and state machine can never disagree. (4) Abort-cutoff watermark: add an additive nullable column `abort_cutoff_ts REAL` to the conversation store (`agents/conversation_sqlite.py` — additive column, old rows unread, no migration, per the standing no-migrations directive); expose `record_abort_cutoff(session_id, ts)` and a read at admission that drops queued/pending input rows whose enqueue timestamp precedes the watermark, with a count-only log line. Wire the write side at the stop path only if R-01's A07-G13 interrupt fix (dashboard stop button claims the generation) is already merged; otherwise land the column + read-side drop + a `# sequences-after R-01 A07-G13` comment and leave the write unwired. (5) Watcher starvation fix in `config/watcher.py`: rework both `create_sourceprep_reindex_callback` and `create_detector_trigger_callback` to a keyed debounce with a fixed first-arrival deadline — record `first_change_ts` on the first change in a burst; the timer fires at `min(first_change_ts + max_window_s, now + debounce_s)` where `max_window_s` (default 30s) is the hard floor deadline after which the callback runs no matter how active the file is. Factor the shared timer/lock/deadline logic into one module-level `_DebouncedCallback` helper class in watcher.py and make both factories thin wrappers, so a third debounced callback never re-introduces the starvation shape. New tests in `halbert_core/tests/` (extend `test_channel_registry.py`; new `test_watcher_debounce.py` or extend `test_config_watcher_on_this_body.py`).

## 4. What NOT to build

Do NOT build the scheduler itself, the prompted heartbeat, the cognition tick, or any caller that actually submits an internal turn — this unit builds the admission representation only; master-plan 03-C is a parked founder decision and its consumer lands later. Do NOT build the transcript-artifact span removal for no-op autonomous turns (OC03-auto-reply-M1) — that is a design requirement gated on founder decision 03-C, not code; record it as a comment/contract note only. Do NOT add a plugin SDK, channel manifests, or per-channel allowlists (the channel layer's D-4 design explicitly declines these). Do NOT create a third sanitizer — the envelope sanitizer must import from `security/text_hygiene.py` (dependency) and never re-implement tag stripping inline. Do NOT touch `mcp/metadata.py:strip_unicode_tags` or `prompts/agent_prompts.py:_CONTROL_TAG_RE` themselves (that convergence is SP-2's job). Do NOT add any model-in-the-loop sanitization — the envelope is deterministic string surgery only. Do NOT write a migration or back-compat shim for `abort_cutoff_ts` (additive column, old rows unread). Do NOT add the terminal channel to the event tee delivery set or change any busy-verb sets. Do NOT name or recommend any AI model anywhere, and no emoji on any surface.

## 8. UX rationale

No new UI surface. The user-visible behaviors: (1) when an internal turn eventually runs (consumer lands with 03-C), its turns appear in the one seamless conversation stamped with `metadata.channel = "internal"` on the user row — recording only, nothing gates on it — and the system still speaks as the computer itself in first person; the internal channel's `default_role="system"` never surfaces a speaker name, and the engaged surface keeps the onboarding `ai_name`, never a raw hostname. (2) "Stop means stopped": after the abort-cutoff lands, text the user typed before pressing stop is never answered by a restarted process — the stop the user already sees in the dashboard today becomes durable across restarts, with no new control. (3) The watcher fix is invisible except that config changes now reliably trigger re-index/detector sweeps within the deadline even while files keep changing (today they can silently never fire). (4) The envelope sanitizer is invisible by design — it only removes content that should never reach prompt assembly. No colours, no emoji, no model names, no settings toggles added; the internal channel is policy data in the registry, not a user-facing connection slot.

## 9. Acceptance criteria

1. `resolve_channel("scheduler")`-style misuse still raises `ChannelRefused` (fail closed); `resolve_turn_cause(modality=None, internal_source=InternalTurnSource.SCHEDULER)` returns the internal channel with `claim_ceiling is ClaimStrength.UNVERIFIED`, and `stamped_claim_source(internal_channel, "dashboard_token")` returns `None` with a `claim_dropped` log record — a machine turn can never mint an ASSERTED claim. 2. Passing both a human modality and `internal_source` is refused; calling with neither behaves byte-identically to today (existing `test_channel_registry.py` pins all pass unmodified). 3. `sanitize_inbound_envelope` strips unicode/control tags (a payload containing tag characters that survive to prompt assembly today comes out stripped) and wraps the body in the bracketed marker pair; the markers nest correctly with the existing `[steered]`/`[/steered]` convention. 4. Watcher: with a fake clock, a file changing every 1s with `debounce_s=5` and `max_window_s=30` fires the callback at or before t=30s (previously never); a quiet 5s gap still fires at first_change+5s; both factories share the one `_DebouncedCallback` helper. 5. Abort cutoff: rows enqueued before the recorded watermark are dropped at admission with a count-only log line; rows after it are untouched; opening a pre-change DB with no `abort_cutoff_ts` column works unchanged (additive, no migration). 6. `CHANNEL_REGISTRY` gains exactly one entry; `CHANNEL_CLAIM_STAMP` gains none. 7. No standing-directive regressions: no model names, no emoji, no new hard dependency, no migration, no second sanitizer implementation.
