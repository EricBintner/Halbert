## 2. User problem

Halbert's desktop and supply-chain posture is unpinned — three real gaps confirmed in the deep-eval and the security audit, none covered by any test or gate today. (1) The Tauri webview renders agent- and RAG-influenced data with no Content-Security-Policy and no deny-by-default outbound-navigation policy: halbert_core/halbert_core/dashboard/frontend/src-tauri/tauri.conf.json has "security": {"csp": null} and "plugins": {"shell": {"open": true}}, src-tauri/capabilities/default.json grants "opener:default" to both the main window and the voice HUD, and at least eight user-facing surfaces hand model-influenced URLs straight to the OS opener via <a target="_blank"> (components/settings/tabs/KnowledgeTab.tsx:478,:659, components/settings/tabs/AboutTab.tsx:58,:64, components/legal/LegalNoticesModal.tsx:139,:147,:193, components/legal/CloudDisclosureModal.tsx:123, components/domain/MarkdownRenderer.tsx:58, pages/GPU.tsx:497). A RAG-poisoned or hallucinated URL is one click from arbitrary scheme/host navigation — the same class as origin CVE GHSA-9f4c-93c8-jc8g, and nothing in the 1,029-test vitest suite pins the posture. (2) Every transitive npm postinstall runs unrestricted as the founder on the host Halbert itself administers: there is no .npmrc anywhere in the repo, no ignore-scripts, no allowScripts map, and package-lock.json records hasInstallScript:true for esbuild in three workspace trees (halbert_core/halbert_core/dashboard/frontend, packages/design-system, packages/model-picker) — the design-system workspace alone pulls a full Storybook 8 tree whose transitive scripts are unaccounted for. (3) The three OSS origin repos Halbert lifts from (openclaw, hermes-agent, Haloysius) drift silently; the polling primitive for cheap change detection already exists (scheduler/monitor_hash.py — persisted source hash, NOT_GATED/BASELINE/SUPPRESS/ALERT_DIFF/SOURCE_ERROR, hash persisted before the agent runs) but no scheduled job points it at any upstream. All three are posture decisions that exist today only as review habit; the fix is to pin each as a deterministic contract. Verdict: RESHAPE — accept the CSP/window-open contract test, the npm install-script allowlist, and the narrowed upstream-tracking job; defer the entitlements test and the broad async rulepack (field 4).

## 3. What to build

Three deliverables, all deterministic, no models, no runtime behavior change beyond outbound navigation policy.

DELIVERABLE 1 — Desktop-security contract test plus the policy it pins (vitest, frontend workspace).
a) New module halbert_core/halbert_core/dashboard/frontend/src/lib/openExternal.ts: a single deny-by-default outbound-navigation gate exporting openExternal(url: string): Promise<boolean>. Explicit allowlist: scheme https only; no http, no file:, no javascript:, no custom protocols, no empty string (the origin test's scheme table verbatim: https ok; http:8080, file:///etc/passwd, javascript:, custom proto, "" all denied). Implementation routes through the Tauri opener plugin already granted in src-tauri/capabilities/default.json ("opener:default"); a denied URL is reported to the caller (returns false, logs the sanitised origin only — never the full URL, which may carry query credentials) and never reaches the opener. Route every existing <a target="_blank"> call site through it: KnowledgeTab.tsx (:478, :659), AboutTab.tsx (:58, :64), LegalNoticesModal.tsx (:139, :147, :193), CloudDisclosureModal.tsx (:123), MarkdownRenderer.tsx (:58 — this is the model-influenced markdown path, the highest-risk one), GPU.tsx (:497). Each becomes an onClick that calls openExternal and prevents default on deny; rel="noopener noreferrer" stays.
b) Set a real CSP in tauri.conf.json replacing "csp": null. Scope it against the dev server (devUrl http://localhost:5173) and Vite's inline styles before writing — the minimum viable posture is default-src 'self'; connect-src 'self' http://localhost:5173 ws://localhost:5173 http://localhost:8000; img-src 'self' data:; style-src 'self' 'unsafe-inline' (Tailwind/shadcn inject inline styles; tightening style-src is explicitly out of scope, field 4). Record the chosen directive string in the test file header as the pinned contract.
c) New test halbert_core/halbert_core/dashboard/frontend/src/__tests__/posture/desktop-security.test.ts (create the posture/ directory; existing tests live colocated or under src/__tests__, e.g. src/App.voiceHudRoute.test.tsx): (i) read and JSON-parse src-tauri/tauri.conf.json (path relative to the frontend root, ../../src-tauri/tauri.conf.json) and assert security.csp is a non-null string containing default-src; (ii) assert plugins.shell is either absent or not {"open": true} at top level, OR that capabilities/default.json grants opener only to windows that route through openExternal — pin whichever final shape deliverable (a) lands, but the assertion must fail on today's shape; (iii) unit-test openExternal against the full scheme table above with the opener plugin mocked (vi.mock @tauri-apps/plugin-opener), asserting denied schemes never call the opener and only the sanitised origin is logged; (iv) a source-scan test over the eight routed call sites asserting no remaining target="_blank" anchor in src/ renders a raw href without going through openExternal (allow static hrefs only for same-origin paths like AboutTab.tsx:64's /docs — pin that exception explicitly). Run with the frontend's existing script: cd halbert_core/halbert_core/dashboard/frontend && npm test (vitest run).

DELIVERABLE 2 — npm install-script allowlist (repo root).
a) New root .npmrc with ignore-scripts=true.
b) The allowlist mechanism: npm has no allowScripts in .npmrc, so pin the exceptions as a script — scripts/check_npm_install_scripts.py (Python, matching scripts/check_contrast.py conventions): parse package-lock.json, collect every packages entry with hasInstallScript===true (today exactly three, all esbuild: halbert_core/halbert_core/dashboard/frontend/node_modules/esbuild, packages/design-system/node_modules/esbuild, packages/model-picker/node_modules/esbuild), compare against an explicit allowlist literal in the script header (package name + the set of workspace paths it may appear in), and exit nonzero on any entry not allowlisted — a new transitive postinstall fails the gate loudly rather than running silently. esbuild is the only allowed package; its postinstall is needed because the binary is platform-specific and ignore-scripts would break the dev/build flow, so after npm ci the script must also verify each allowlisted esbuild has its platform binary present (@esbuild/darwin-arm64 etc.) and fail with a message telling the developer to run node node_modules/esbuild/install.js for that workspace only — the visible-exception workflow FD-6 calls for.
c) Wire the gate into .github/workflows/ci.yml as one step in the existing test job (alongside the suite-census meta-gate pattern at ci.yml:14-116): python3 scripts/check_npm_install_scripts.py. Pure stdlib, no new dependency — the Haloysius two-hard-dependency contract is untouched.

DELIVERABLE 3 — Upstream-tracking job (scheduler config only, no new task class).
Register one new detector_sweep-class job, named exactly upstream_tracker, by adding it to DEFAULT_MONITOR_HASH_JOBS in halbert_core/halbert_core/scheduler/monitor_hash.py:34 (frozenset({"detector_sweep", "upstream_tracker"}) — one deliberate line, matching the named-set design). ## 8. UX rationale

No new UI surfaces and no visible chrome changes; the only user-perceptible behavior is in link handling. When a rendered link (chat markdown, knowledge-base document URL, legal notice, disclosure modal) is https, clicking it opens the default browser exactly as today — same hover affordance, same pointer, no copy changes. When a model-influenced URL is not https (file:, javascript:, custom scheme, empty), the click is a silent no-op from the user's perspective: no dialog, no toast, no error theatre — the system simply does not navigate, and the sanitised origin is logged for the findings trail. This matches the Halbert frame: the computer acts as its own steward, grounded in the measured fact of the URL's actual scheme, without narrating a security decision at the user or naming any model. The developer-facing surfaces are deliberate and loud where they should be: a new transitive npm postinstall fails CI with the package name and workspace path printed (the exception is the visible thing, per the recommended FD-6 default), and an upstream drift produces a .handoff/REVIEW-NEEDED-<repo>-<date>.md stub in the correspondence tree the founder already reads — never a notification, never an auto-patch, never a conversation message. Nothing appears in the dashboard; there is no posture badge, no banner, no settings toggle.
