## 1. Packet

**reconnect_supervisor** — Reconnect supervisor primitive.

## 2. User problem

Halbert has three live reconnect loops, each hand-rolled and each wrong in a different way, with no shared primitive — and the FINAL-CRITICAL-DISCOVERY-BACKLOG (§3.9) names reconnect supervision as one of the cross-cutting primitives to build once before fanning out dependent packets. (1) `halbert_core/halbert_core/integrations/home_assistant/ha_event_stream.py:167-169` runs a flat `await asyncio.sleep(5)` retry loop: no backoff growth, no jitter, no cap, no stability window, so a flapping HA websocket costs one reconnect attempt every 5 seconds forever and a Wi-Fi flap + HA restart produces a synchronized retry storm at exactly the same cadence as every other consumer. (2) `halbert_core/halbert_core/mcp/health.py` grew its own per-server backoff (`_delay_for` at :488-494 doubling from `_backoff_start` capped at `_backoff_cap`, `_arm_backoff` at :496-501) plus a bespoke "proven session" reset (`_probe_succeeded` at :434-457, A17-G14) — that proven-session rule is exactly a stability window, written once, MCP-specific, and unavailable to anyone else. (3) VMV-4's deep-eval confirms the voice event tail and GW-A's SSE/WS event stream need the same mechanism for "reconnect without loss," and SCHED-P5's thaw detector (OC16-C8, laptop-suspend late-tick reconnect) needs it too — today none of them can borrow mcp/health.py's version because it is welded to `ServerHealth` records and the MCP probe sweep. `utils/retry.py:26` (`exponential_backoff_retry`) is a per-call-site decorator for function retries, not a long-lived connection supervisor: it has no stability window, no bounded outbound queue, and no notion of "session proven," so it cannot serve these consumers and must not be stretched into one. The standing rules forbid duplicate primitives; three half-copies of backoff already exist and GW-A (Wave 1, ACCEPT) is about to need a fourth. This unit builds the one supervisor the backlog's Wave-0 table implies (it is the missing Wave-0 row for §3.9) so every consumer adopts it instead of growing a fourth and fifth copy.

## 3. What to build

Create `halbert_core/halbert_core/net/__init__.py` and `halbert_core/halbert_core/net/reconnect_supervisor.py` implementing one `ReconnectSupervisor` class per the registry notes (backoff/jitter/stability-window + bounded drop-oldest queue), modeled on the openclaw reference `src/infra/agent-events.ts:265` (seqByRun) for the sequence-stamping half of the queue. Concretely: (1) Constructor takes `name: str` (for log lines, e.g. "ha-event-stream"), `base_delay: float = 1.0`, `max_delay: float = 60.0`, `factor: float = 2.0`, `jitter_ratio: float = 0.25`, `stability_window: float = 30.0`, and `queue_max: int = 256`. No other Halbert imports beyond stdlib (`asyncio`, `random`, `time`, `collections.deque`, `logging`) — this is a leaf primitive, and the Haloysius two-dependency contract is untouched since it adds zero dependencies. (2) `next_delay() -> float`: computes `min(base * factor**attempt, max_delay)` then applies symmetric jitter `delay * (1 ± jitter_ratio * random())`; increments the internal attempt counter. (3) `note_connected() -> None`: stamps the connect time on the monotonic clock. (4) `note_disconnected() -> None`: if the session lived >= `stability_window` seconds, reset attempt counter to 0 (this is the general form of mcp/health.py's A17-G14 proven-session rule); otherwise keep the counter so a connect-then-die server keeps charging backoff. (5) `async wait_before_retry() -> None`: sleeps `next_delay()`; cancellation-safe (propagates `asyncio.CancelledError`). (6) A bounded outbound queue: `enqueue(item) -> bool` appends to a `deque(maxlen=queue_max)` with drop-oldest semantics and returns False when an item was evicted (so the caller can log the drop); `drain() -> list` returns queued items in order and clears — this is what GW-A's event replay and VMV-4's turn-event tail use to buffer outbound events while the socket is down, stamped with a monotonically increasing per-run sequence number (`next_seq()`), per the seqByRun reference. (7) `snapshot() -> dict` returning `{name, attempts, connected, queue_depth, dropped_total, next_delay}` for doctor/diagnostics surfaces later (DIAG-01 registry will consume this; this unit only exposes the method). Write tests in `halbert_core/tests/test_net_reconnect_supervisor.py` covering: delay sequence doubles then caps; jitter keeps delay within the declared band (seed `random`); attempt counter resets only after a session older than the stability window and survives a connect-then-immediate-drop; queue evicts oldest at capacity and reports the drop; `wait_before_retry` is cancelled cleanly by `asyncio.wait_for` with a short timeout. Do NOT touch `mcp/health.py`, `ha_event_stream.py`, or any consumer in this unit — adoption is the consumers' packets (GW-A, VMV-4, VMV-2, MCP-C, SCHED-P5), each of which swaps its bespoke loop for this class in its own branch. Add `net/` to no registries; it is a plain package importable as `halbert_core.net.reconnect_supervisor`.

No SSE/WS event-stream reconnect logic, no `since_seq` resume parameter, no typed error envelope — that is GW-A's ACCEPT packet, which consumes this primitive plus its own `dashboard/event_replay.py`. No frontend reconnect owner: OC23-C12 (the 3–5s fixed SSE backoff in the dashboard TypeScript) was accepted as low priority inside SURFACE-01 and is a separate frontend item, not this Python module. No new `utils/retry.py` changes — the existing `exponential_backoff_retry`/`async_exponential_backoff_retry` decorators keep serving per-call function retries; this unit does not merge, deprecate, or wrap them (they solve a different problem: bounded function retries vs. long-lived connection supervision). No LaunchAgent/supervisor or process-lifecycle work — SCHED-P5's thaw detector only borrows the supervisor's stability-window semantics for its post-suspend reconnect; the LaunchAgent tail of SCHED-P5 stays deferred behind its founder decision per the backlog. No config-file surface: delays/windows are constructor parameters chosen by each consumer, not user settings. No networking code at all — this module never opens a socket; it is a pure timing/queue state machine.

## 8. UX rationale

No user-facing surface: this is an internal timing primitive with no UI copy, no colours, no emoji, no model naming — the standing directives are trivially satisfied because nothing renders. The user-visible effect arrives only through consumers: after VMV-4 adopts it, a Wi-Fi flap no longer means the HA event stream hammers Home Assistant every 5 seconds while the laptop is on battery, and after GW-A adopts it, a reloaded dashboard tab reconnects with jittered backoff instead of a thundering fixed-cadence retry against the backend it shares with the scheduler tick. The only surface the module itself exposes is `snapshot()` — a dict a doctor check (DIAG-01) can later render as "the home-assistant link reconnected 4 times in the last hour, currently healthy" in the machine's first person, grounded in measured data. Log lines use the consumer-supplied `name` ("ha-event-stream", "mcp:<server>") — slot labels and subsystem names only, never a model name. The queue's drop-oldest eviction must log one bounded line per eviction burst (not per item) so a long outage cannot flood the log — one line: "reconnect queue for <name> full; dropped N oldest events".

## 9. Acceptance criteria

1. `halbert_core/halbert_core/net/reconnect_supervisor.py` exists and imports with only stdlib dependencies (`python -c "import halbert_core.net.reconnect_supervisor"` succeeds under the venv). 2. Delay sequence: with base=1.0, factor=2.0, max=8.0, jitter_ratio=0, successive `next_delay()` calls return exactly 1.0, 2.0, 4.0, 8.0, 8.0. 3. Jitter band: with jitter_ratio=0.25, 1000 samples of the first delay all fall within [0.75, 1.25]. 4. Stability window: a session that stays connected >= stability_window resets the attempt counter on `note_disconnected()` (next delay returns to base); a connect-then-drop inside the window does not reset (delay keeps growing). 5. Queue: at queue_max capacity, `enqueue` evicts the oldest item, returns False, increments `dropped_total`, and `drain()` returns items in FIFO order with monotonically increasing per-run sequence numbers from `next_seq()`. 6. Cancellation: `wait_before_retry()` inside `asyncio.wait_for(..., 0.05)` raises `asyncio.TimeoutError` at the caller and propagates `CancelledError` when the task is cancelled directly. 7. No existing file is modified: `git diff --name-only` for the unit's commit shows only the two new files (`net/__init__.py`, `net/reconnect_supervisor.py`) plus the test file. 8. `mcp/health.py`, `ha_event_stream.py`, and `utils/retry.py` are byte-identical before and after this unit (adoption is deferred to consumer packets).
