## 1. Packet

**TT-04a** — PTY reattach + foreground-command guardrail.

## 2. User problem

Two live defects on the watched-terminal surface, both verified on main @ fbd725e9. (1) PTY reattach is broken from the user's side: the backend deliberately survives disconnect — /ws/terminal/{session_id} in dashboard/routes/websocket.py:155-158 detaches the client and leaves the PTY alive for reattach, and streaming/pty.py keeps a 1 MiB scrollback (_DEFAULT_BUFFER_BYTES, get_buffer()/_replay_buffer) — but the frontend throws that away: useTerminalSessions.ts:313-321 ws.onclose marks any still-'running' session status='done' with exitCode=-1. Laptop sleep, a wifi flap, or a Tauri window reload shows a live, still-running shell as exited with code -1 while the process keeps running. The interactive tile goes dead (isInteractive() at :332 returns false once status!='running'), keystrokes are refused, and there is no reconnect path at all — no retry, no replay fetch, no distinction between "child exited" (msg.type==='exit' at :307) and "socket dropped" (onclose). This is the founder-named surface — user shells stay but are watched by the AI (ROADMAP TERM-1) — and it lies about liveness exactly when the network is least reliable. (2) The foreground-command guardrail does not exist: a model that runs `npm run dev`, `vite`, `uvicorn`, `next dev`, `nodemon`, or `docker compose up` as a plain foreground terminal call burns the full ToolExecutor.DEFAULT_TIMEOUT=30s (tools/executor.py:136, :891) and returns a timeout error for a command that is behaving exactly as designed. Worse, a model that has learned to dodge the timeout reaches for `nohup ... &`, `setsid`, or `disown`, which detaches the process from every watched surface Halbert owns — no PTY, no scrollback, no terminal_block row, no reaper visibility — the exact opposite of the watched-terminal posture. The terminal tool already accepts background=true (executor.py:893, :911-912, _run_command_background:1036) but nothing nudges the model toward it, so the correct path is invisible at the decision point. These are Half A of deep-eval TT-04 (RESHAPE verdict in FINAL-CRITICAL-DISCOVERY-BACKLOG-2026-09-11.md:145: "Ship PTY reattach and guardrails. Defer background registry/wake lane"): items HM18-C18 (reconnect state machine), HM07-C8 (foreground-command guardrail), OC03-C12 (progress labels), OC24-C10 (bounded wait on a watched session).

## 3. What to build

Two target files plus their test modules; lane C (tools/safety.py, merge 2/4 after TT-03) and lane-adjacent session_manager work sequenced after CSC-06 and GW-A land (deps). Build four things. (1) Server-side liveness truth for reattach, in streaming/session_manager.py: extend the TerminalSessionManager surface so a client can distinguish "child exited" from "socket dropped, child alive" — the data already exists (session.exit_code, PTYSession.read_chunk(), the reaper's liveness probe in _reap_once:239) but is not exposed as one authoritative call. Add `session_liveness(session_id) -> dict` (or extend list_active():119) returning {alive: bool, exit_code: Optional[int], attached_clients: int, last_activity_monotonic: float}; alive is exit_code is None AND the child pid still exists (os.kill(pid, 0) probe, the same check _reap_once makes — one implementation, not a second). The websocket route already leaves the session alive on detach (websocket.py:155-158); this unit must NOT change that behavior, only make it queryable. (2) Reconnect with bounded budgets in session_manager.py, consumed by the frontend hook: a reattach is `manager.get(session_id)` + fresh attach_client() + replay via the typed replay frame CSC-06 delivers (pty.py get_buffer()/__replay__ seam) — this unit wires the manager side: an `attach_with_replay(session_id)` helper that returns the session plus get_buffer() bytes in one call so the route cannot forget the replay, and a bounded-wait primitive `wait_for_prompt(session_id, timeout_s, poll_s)` (OC24-C10): poll is_at_prompt() (session_manager.py:163) until true or deadline, on timeout return {timed_out: True, tail: last N bytes of get_buffer()} as evidence — deterministic, no model, the OpenClaw wait-for-text.sh pattern ported to the manager we already own. Default budget: timeout 30s, poll 0.5s, tail 4 KiB. The frontend half (rewriting onclose to attempt reattach with an 8s wedged-CONNECTING force-close and 1s resume-burst throttle before falling back to 'done') lives in useTerminalSessions.ts and is authorized only if the packet's target-file list is amended at dispatch; the manager must expose everything that frontend needs so the hook stays thin. (3) The foreground-command guardrail in tools/safety.py (HM07-C8): a pure synchronous function `foreground_background_nudge(command: str) -> Optional[str]` on ToolSafetyFramework, called from _classify_command (safety.py:845) after the blocked checks and before the rule table, that returns guidance text or None. Detect three anti-patterns over a quote/heredoc-masked copy of the command (reuse the masking helper TT-03 lands in lane C ahead of this packet — if TT-03 has not merged, mask inline with a local _strip_quotes equivalent, do not block on it): (a) shell-level detachers — nohup, setsid, disown as a command word; (b) a trailing `&` outside quotes; (c) a recognized long-lived foreground pattern: npm/pnpm/yarn run dev|start|serve, vite, uvicorn, gunicorn, python -m http.server, next dev, nodemon, docker compose up (anchored alternation, case-sensitive on the binary, word-boundaried). The result is GUIDANCE, never a rejection: risk classification is unchanged (the command still classifies and runs as today); the nudge rides as an optional `guidance: Optional[str] = None` field added to SafetyCheckResult (safety.py:45-55 — additive dataclass field, no call-site breakage) and the executor appends it to the tool result text the model sees: "This looks long-lived. Re-send as terminal(command=..., background=true) so I can keep watching it; nohup/& detaches it from me." First-person computer voice, no model names, no emoji. (4) Progress labels (OC03-C12) at the same seam: when the guardrail fires, the label format it nudges toward is part of the guidance — background=true calls should carry a short label (the command's own words, exec-relevant flags fronted) so the task card and progress surfaces read "vite dev (background, pid …)" rather than a raw 200-char command line; implement the label formatter as a small pure function in safety.py (directory-brace collapsing is explicitly out — that is the OC03 origin's multi-file listing case, not ours; ours is single-command: strip the cwd prefix, front `elevated`/`pty` flags if the classifier already knows them, truncate at 80 chars on a word boundary). The label is data the terminal_block/task-card surfaces can consume; wiring it into StatusStrip.tsx is NOT this unit.

## 8. UX rationale

The watched-terminal promise is "your shells stay yours, and I keep watching them" — today that promise breaks in both directions this unit fixes. After the fix, a wifi flap or laptop sleep no longer turns a live shell into a tombstone reading "exited -1": the tile reattaches, the scrollback (up to 1 MiB, already buffered server-side) replays, and the session resumes as running with its real state. When the process truly has exited, the exit frame — not a socket close — is what says so, with the real code. The user never sees a reconnect spinner or a "connection lost, retrying" chrome; the shell simply never falsely dies. On the guardrail side, the failure mode today is invisible friction: the model runs npm run dev, waits 30 seconds, and reports a timeout for a dev server that started fine — or worse, learns to hide long-lived processes from Halbert behind nohup &, after which the watched surface shows nothing at all. After the fix the tool result itself carries the nudge in the computer's first person ("this looks long-lived — re-send it with background=true so I can keep watching it"), the model re-sends once, and the command lands on the tracked background path where its progress label reads as a short human line ("vite dev, background") instead of a raw command wall. No new settings, no new panels, no model names, no emoji, no colors touched; the conversation stays one seamless surface and the change is felt as the terminal simply telling the truth about what is alive.

## 9. Acceptance criteria

1. Liveness truth: with a real PTY session spawned through TerminalSessionManager.spawn() running `sleep 60`, session_liveness() (or the extended list_active() row) reports alive=True, exit_code=None; after the socket-side client detaches (no exit frame sent), it still reports alive=True — the manager's answer never flips to dead on transport loss. After the child exits, alive=False with the real exit code. 2. Reattach with replay: spawn a session, emit output ("echo hello-$RANDOM"), detach the client, call attach_with_replay() — the returned bytes contain the earlier output (scrollback survived), and attach_client() count is back at 1 so the reaper exemption holds. 3. Bounded wait: wait_for_prompt() on a session sitting at a shell prompt returns promptly with timed_out=False; on a session running `sleep 30`, it returns at the deadline with timed_out=True and a non-empty tail payload; total elapsed wall time never exceeds timeout_s + one poll interval. 4. Guardrail: _classify_command("npm run dev").guidance is a non-empty string steering to background=true; same for `nohup longjob &`, `setsid x`, `uvicorn app:api`, `docker compose up`, and a bare trailing `&`. Quoted false-positives do not fire: `echo "nohup &"`, `grep 'docker compose up' log.txt` classify with guidance=None. Risk levels are byte-identical to before for every one of these commands (guidance only, never reclassification). 5. Labels: the formatter strips a leading cwd, fronts elevated/pty markers, truncates at 80 chars on a word boundary, and never raises on empty/binary-ish input. 6. Frontend seam (if the hook file is in scope at dispatch): on ws.onclose without a prior exit frame, the session is not marked 'done' until a reattach attempt against session_liveness has failed within its budget; on successful reattach the replayed bytes appear in s.output exactly once (no duplication with the pre-close tail). 7. No regression: the existing suites for both touched files pass with the arch-prefixed runner, and any failure is checked against the known-red baseline (test_agent_model_override.py, test_agent_model_selected_event.py, test_no_model_names_in_user_facing_source.py, test_num_ctx.py, ~23 failures @ 2026-09-11) — a failure is this packet's only if absent from that baseline.
