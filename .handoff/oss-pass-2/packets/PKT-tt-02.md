## 2. User problem

TT-02 (RESHAPE, verified against main @ 627ae4b8; R-09 confirmed merged via commit 7edf3908 which landed child_env() at mcp/client.py:153 with CHILD_ENV_ALLOWLIST at :131 and _CHILD_ENV_DENY_PREFIXES at :148). R-09 fenced the stdio MCP child environment but scoped itself to mcp/client.py; the same leak class is live on two other surfaces plus two boundary defects the merged remediation never touched. (1) Every PTY shell Halbert runs inherits the full parent environment: streaming/pty.py:316 does child_env = dict(os.environ) then os.execvpe("/bin/sh", ..., child_env) at :321 for every spawned PTY, and streaming/agent_pool.py:83-88 spawns pool shells via TerminalSessionManager.spawn without passing env, so env=None flows to PTYSession (session_manager.py:99) and the same dict(os.environ) fires. Watched user shells, agent-pool shells, and every terminal tool call all run with HALBERT_API_TOKEN and ANTHROPIC_API_KEY visible in /usr/bin/env; a staged `env | curl …` exfiltrates both. Same audit family as A17-G1 on a different surface (HM05 residual). (2) No positive denial marker: R-09's allowlist and any PTY fence both work by absence, but absence alone cannot distinguish "fenced descendant" from "orchestrator" — a process checking `if "HALBERT_API_TOKEN" in os.environ` to decide trust gets a false negative and self-promotes. A descendant must be fenced by a value that is PRESENT (HALBERT_CHILD_CONTEXT=<kind>), never by a key that is missing (HM05-M4). (3) Background offloads inherit the caller's security ContextVars: 37 bare asyncio.to_thread sites exist (mcp/client.py 7, dashboard/routes/being.py 5, dashboard/routes/agent.py 4, vision_tools/become_tool/guest/state_machine 3 each); asyncio.to_thread copies the current contextvars.Context into the worker, so current_turn_claim (tools/executor.py:50), current_speaker_role, current_turn_channel (agents/channels.py:255) ride along. The cognitive-loop tick at home/cognitive_loop.py:294 runs advance_turn via asyncio.to_thread — autonomous work executed under whatever user-turn identity was bound when the tick fired, violating "autonomous work is never attributed to a user turn" (HM05-M3). (4) Security-load-bearing binaries resolve from bare PATH: streaming/sandbox.py:98-100 resolves bwrap and sandbox-exec via shutil.which; crypto/storage.py:227 does the same for security and :271 for secret-tool. A hijacked sandbox-exec earlier in PATH silently defeats the sandbox — every command the agent believes is sandboxed runs unsandboxed (OC12-C4, medium: requires an attacker already able to write a PATH directory, but the payoff is total).

## 3. What to build

Four deterministic changes, all reusing R-09's proven pattern; no second allowlist table. (1) Shared subprocess-env builder + PTY env fence: extract the R-09 allowlist logic (CHILD_ENV_ALLOWLIST names, XDG_ prefix keep, DYLD_/LD_ deny prefixes, config-env merge with deny-prefix warning) from mcp/client.py:131-178 into tools/subprocess_env.py as build_subprocess_env(baseline=os.environ, extras=None, *, kind, profile). mcp/client.py:153 child_env() becomes a thin wrapper returning build_subprocess_env(extras=config_env, kind="mcp") — public shape and deny-prefix warning unchanged, R-09's tests stay green. streaming/pty.py:316-321 replaces child_env = dict(os.environ) with build_subprocess_env(extras=self._env, kind=kind, profile=...); the session kind already threaded through TerminalSessionManager.spawn (session_manager.py:99) is plumbed into PTYSession.__init__ so the fence knows user vs agent-pool vs terminal-tool. _PAGER_NEUTERED (pty.py:317) moves into the extras merge. Founder-facing policy seam: one allowlist table, but a profile argument ("user" vs "agent") widens the locale set (LANG/LC_*/TERM) for watched user shells — the standing rule is user shells stay WATCHED, never adopted, and a watched shell that loses LANG/TERM breaks the founder's own terminal — while the agent-pool profile stays minimal; both strip credential-shaped names. (2) Positive denial marker: build_subprocess_env always sets HALBERT_CHILD_CONTEXT=<kind> (mcp, pty-user, pty-agent-pool) on every returned env; grep halbert_core/ for trust-by-absence checks on HALBERT_API_TOKEN and switch each to HALBERT_CHILD_CONTEXT absence; record the marker name in DECISIONS.md next to the R-09 row. (3) Empty-Context offload helper: new utils/context_offload.py with async def to_thread_detached(fn, /, *args, **kwargs) running fn under an explicitly empty contextvars.Context (ctx = contextvars.Context(); loop.run_in_executor(None, ctx.run, fn, *args)); migrate only autonomous machine-initiated offloads — the canonical home/cognitive_loop.py:294 becomes to_thread_detached — via a grep-plus-judgment sweep over the 37 sites; leave user-turn continuations (dashboard routes answering their own request) on plain asyncio.to_thread since they should keep the caller's identity. (4) Trusted-executable check: add resolve_trusted_executable(name) in exactly one place (utils/platform.py or tools/subprocess_env.py) — resolve shutil.which(name), verify os.path.realpath lives under the trusted directory set (/usr/bin, /bin, /usr/sbin, /sbin, /opt/homebrew/bin on macOS, /usr/local/bin) and is not world-writable (stat.S_IWOTH clear); fail closed (backend reports unavailable, deterministic first-person log line) otherwise. Wire into the four call sites: streaming/sandbox.py:98 (bwrap), :100 (sandbox-exec), crypto/storage.py:227 (security), :271 (secret-tool). Per "machine is the project," the trusted set is a capability boundary (OS install dirs), not a user-configurable path list. Public shapes preserved: child_env() signature unchanged, PTYSession gains one keyword, sandbox/crypto behaviour identical on a healthy system. If Wave-0 subprocess_env has not landed, this unit builds the minimal version there and MP-6/R-09 follow.

## 8. UX rationale

No new surface, no copy change, no colour, no emoji. Nothing the founder sees changes shape — what changes is what a spawned shell can read. A watched user shell still behaves exactly like the user's terminal (locale and TERM survive), but `env` no longer prints HALBERT_API_TOKEN or ANTHROPIC_API_KEY; if the agent is ever tricked into staging `env | curl …`, the exfiltration finds nothing. The system does not announce this — it is a boundary, not a feature — but if a sandbox or credential backend resolves to an untrusted binary, the log line is deterministic and first-person: "I refused to use sandbox-exec at /tmp/…: it is not in a trusted system directory. Sandboxing is unavailable." — the computer stating what it measured, never an assistant paraphrase, never a model name. Commands remain staged-never-executed from the UI per the standing rule; this unit only changes the environment an already-approved execution runs in. The positive denial marker is invisible to the user but load-bearing for any future code that asks "am I the orchestrator?" — the answer is now a value that is present, never a key that is missing.
