## 1. Packet

**CSC-03** — Conversation survives the process (crash-survival).

## 2. User problem

A crash or force-quit of the dashboard process mid-turn loses the end of the one seamless conversation with no acknowledgement. Verified on main today: (1) NO signal handler exists anywhere in the serving path — grep for `signal.signal` / `set_exception_handler` across `halbert_core/halbert_core/dashboard/` and `halbert_core/halbert_core/agents/` returns nothing, so SIGTERM (launchd, Tauri shell quit, `make dev-restart`) kills the process with no flush; whatever `append_message` had not yet committed is simply gone. (2) `conversation_sqlite.py:1535-1555` documents that `append_message` returns None after a WARNING when the write fails and "nothing is left behind on failure" — a crash between the model finishing and the row committing loses those messages with no spool and no recovery. (3) The boot sweep does exist — `run_conversation_boot_hooks()` in `dashboard/app.py:140-177` calls `ThreadManager.mark_interrupted()` → `conversation_sqlite.py:1722 mark_in_progress_interrupted()`, flipping stale `in_progress` rows to `interrupted` so the timeline renders "(Halbert restarted here)" — but it cannot distinguish a crash from a clean restart (every quit looks identical), and nothing SPEAKS: the next turn after a crash opens as if nothing happened. For a steward whose entire value is continuity — one seamless conversation, no conversation list, first person grounded in measured data — silently resuming after losing the tail of a turn is the worst failure shape. The founder runs this as a .app on his own machine; crashes and force-quits are routine, not theoretical. The registry notes restore this unit's core after the RESHAPE verdict: R-12 landed the transcript-side twin (the `interrupted` row taxonomy in `_end_turn`, state_machine.py:1279-1317), and what remains is the process-side half — the signal handler, the crash-vs-clean classification, the spoken line, and the flush. The section file calls the SIGTERM handler the "highest value-per-line item in the unit."

## 3. What to build

Lane A+F, four mechanisms, one install site. (1) CHAINED SIGTERM/SIGINT FLUSH HANDLER in `halbert_core/halbert_core/dashboard/__main__.py` `main()` — installed AFTER `app = create_app(...)` and BEFORE `uvicorn.run(...)` (the one place that is before uvicorn takes the signals), and identically in the `__main__` guard of `dashboard/app.py:1793-1798`. The handler is chained: it runs a flush hook (best-effort, bounded by a ~2s deadline, never raises) that ends any non-running turn scope via the state machine's existing `_end_turn("interrupted")` path and forces the conversation store's connection to commit/checkpoint, then re-raises the default handler / falls through so uvicorn's own shutdown proceeds. Registration goes through `signal.signal(signal.SIGTERM, ...)` / `SIGINT`, storing and invoking the previous handler. (2) DURABLE `.clean_shutdown` MARKER: the same flush hook writes `<data_dir>/.clean_shutdown` (resolve the dir exactly as `conversation_sqlite.py:145-150` does — `HALBERT_DATA_DIR` env, else `utils.paths.data_dir()`); at startup, `run_conversation_boot_hooks()` in `app.py` checks for the marker's absence from the previous run BEFORE unlinking it, and classifies this boot as crash-vs-clean — the result extends the existing `result` dict (`result["boot"] = "crash" | "clean"`) and is logged with the existing boot-hooks line. Mark-and-report only: no closing, deleting, or migrating of anything (no-migrations directive; founder ruling required for anything stronger). (3) FIRST-PERSON SPOKEN LINE: when the classification is "crash" AND `mark_interrupted()` returned ≥1, the next turn's context gets one first-person line in the interrupted-turn marker family — "I was cut off while …" grounded in the interrupted row's measured data (what the turn was doing from its `last_activity_note`/query), never a model-generated apology. This is the computer speaking about its own measured state, exactly the standing voice rule; the count and the note come from the store, not from generation. The delivery point is the same seam that already renders "(Halbert restarted here)" — extend, don't add a second surface. (4) SHUTDOWN FLUSH-TO-SPOOL + LOOP-EXCEPTION HANDLER as riders at the same install site: the flush hook also drains any pending failed-write buffer (the path where `append_message` returned None) into a spool file beside conversations.db so nothing is left behind on failure during shutdown; and `loop.set_exception_handler` on the running asyncio loop collapses benign peer-hangup noise (ConnectionResetError on client disconnect) into one debug log line instead of a traceback storm. Reuse the EXISTING machinery — `ctx.last_activity`/`last_activity_note` (`states.py:337-347`, already built), `mark_in_progress_interrupted` (`conversation_sqlite.py:1722`), `_end_turn` reason taxonomy (`state_machine.py:1279-1317`), `run_conversation_boot_hooks` (`app.py:140`). This unit builds the process-side ring around them; it does not rebuild the transcript side.

## 7. Effort

**M** — M is correct and the registry notes support it. The mechanisms are individually small but the install sites are load-bearing and must be threaded through three files without breaking the serving path: the chained handler has to compose with uvicorn's signal handling (get it wrong and SIGTERM either doesn't flush or doesn't stop the server), the boot classification has to sequence marker-check → sweep → marker-unlink inside the existing `run_conversation_boot_hooks` without changing its never-raises contract, and the spoken line has to reach the turn-context seam without a new surface. What keeps it at M rather than L: the interrupted-turn marker's transcript twin, the `ctx.last_activity` stamp, the end-reason taxonomy, and the boot sweep all ALREADY exist on main — this unit is the process-side ring around landed machinery, not a from-scratch build. What keeps it from being S: two entry points (`__main__.py` and `app.py`'s `__main__` guard) both need the handler, the spool drain touches the failure path of `append_message` whose contract is documented in conversation_sqlite.py:1535-1555, and the verification requires a real kill -TERM of a live server, not just unit tests. The deep-eval itself names the SIGTERM handler the highest value-per-line item — small, but not free.

## 8. UX rationale

One visible moment, one surface, zero new UI. After a crash, the next turn in the one continuous conversation carries the machine's own first-person acknowledgement, grounded in what the store actually measured: "I was cut off while <what the interrupted turn was doing>." — the computer speaking about its own state, not an assistant apologising. This rides the EXISTING "(Halbert restarted here)" timeline seam; it extends that moment with the spoken line rather than adding a banner, toast, modal, or panel. On a clean shutdown and restart: nothing. The classification is silent when there is nothing to say — a steward does not narrate its own clean exits. The interrupted row's rendering stays exactly as today. No settings toggle, no conversation list, no new colour (anything rendered inherits the existing restart-seam styling from shared-tokens), no emoji, no model names, no raw hostname. The only other user-perceptible change is absence: fewer lost tails of turns, and no traceback storm in the log when a browser tab hangs up mid-stream.

## 9. Acceptance criteria

(1) SIGTERM during an in-progress turn: the flush hook runs (turn ended via the interrupted path, store committed, `.clean_shutdown` written) AND the process still exits to uvicorn's normal shutdown — verified by exit code and by the marker's presence. (2) SIGKILL or crash (no handler): on next boot, `run_conversation_boot_hooks` classifies the boot as crash (marker absent), `mark_interrupted()` heals the stale in-progress rows, and the classification appears in the boot result dict and log line. (3) Clean quit then boot: classification is clean, no spoken line, marker written again on the way down. (4) Crash with ≥1 interrupted row: the next turn's context contains the first-person "I was cut off while …" line naming the interrupted turn's activity from measured data, deterministically — no model call in that path. (5) The `append_message` failure path during shutdown drains to the spool file instead of vanishing. (6) Peer-hangup (ConnectionResetError from a disconnected client) produces one debug line via the loop exception handler, not a traceback. (7) All of the above hold with `HALBERT_DATA_DIR` pointed at a temp dir, so no test ever touches production data. (8) No behaviour change on the happy path: a normal turn, a normal quit, a normal boot are byte-identical to today except the marker file.
