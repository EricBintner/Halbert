## 2. User problem

The agent's tool-dispatch path in `halbert_core/halbert_core/agents/state_machine.py` mishandles weak local models — Halbert's primary target — in five verified ways. (1) Malformed tool arguments are coerced, not refused: `halbert_core/halbert_core/model/client.py:457-465` (`_normalise_tool_calls`) swallows a JSON parse failure and dispatches the tool with `{}`, so a local model emitting truncated JSON gets `terminal {}` / `write_file {}` executed against empty args, burning one of five loops; `_already_called` may then refuse the corrected retry as a duplicate. The verifier calls this "the most likely real-world failure in the set." (2) The repeat guard is blunt in the other direction: `_already_called` (`state_machine.py:3521-3532`, applied on the general dispatch path at `:3475-3484` and meta path at `:3437`) refuses any (name, args) pair already settled this turn and forces REFLECTING — so the canonical edit-then-rerun sequence (failing `run_command <test>`, a `write_file` edit, the same command again) is refused and the turn ends. There is no failure classification, no tolerant-tools set, no progress reset, and no argument-churn or ping-pong detector; `max_loops=5` (`state_machine.py:306`, checked at `:1486-1497`) is the only ceiling. (3) The interactive path bounds iterations only, not tool calls: a model returning 40 tool calls in one message is unbounded (the script path already has `DEFAULT_TOOL_CALL_BUDGET=25` in `tools/execute_code.py:56` and `script_rpc_host.py:43-46,105-121`; the interactive path has nothing). (4) A late tool result can land in a newer turn's context: `agents/turn_activity.py:24-70` provides generation claims for the abort itself, but `tools/executor.py` has no abort/generation parameter and nothing detaches a late settlement — a coroutine cannot truly be cancelled, so its result must be detached from the aborted generation instead. (5) When a turn dies after a side-effecting tool started, the next turn is silent about a possibly-completed destructive action: observations die with ctx; the boot sweep (`conversation_sqlite.py:1722 mark_in_progress_interrupted`, `threads.py:512-513`) marks rows `interrupted` but persists no effect marker. Verdict in FINAL-CRITICAL-DISCOVERY-BACKLOG-2026-09-11.md: ACCEPT, effort S, Wave 1 (no founder decision; A07-G11 auto-resume is explicitly out of scope).

## 3. What to build

Build tool-loop guardrails and malformed-call recovery across five ordered work items, sequenced as the section doc orders them (HM01-C13 first).

1. REFUSE, DON'T COERCE, UNPARSEABLE ARGUMENTS + 3-STRIKE REPAIR BUDGET (HM01-C13). In `halbert_core/halbert_core/model/client.py` `_normalise_tool_calls` (`:457-465`), stop substituting `{}` on parse failure: mark the call with a new flag (e.g. `args_invalid: True`) carrying the raw fragment. In the dispatch path (`state_machine.py` `_handle_planning` around `:3426-3499` and/or `_handle_executing` at `:4222+`), an `args_invalid` call returns a structured observation — "arguments did not parse; resend the call with valid JSON" — WITHOUT executing and WITHOUT recording a settled tool call (so `_already_called` never sees it). Add close-name repair for unknown tools: when `tool_name` matches no registered tool, compute edit distance against the registry; exactly one candidate within distance 2 → rewrite the name and note the repair in the observation; zero or ≥2 candidates → structured "unknown tool" result listing the candidates, never the bare `Unknown tool: {name}` from `tools/executor.py:589`. Track a per-turn strike budget of 3: strikes advance only when a turn iteration produces NO valid tool call; at strike 3, exit gracefully with a partial response (transition to REFLECTING with an observation saying the tool sequence was abandoned). Deterministic only — no model in the repair ladder. Tests: truncated JSON never reaches a handler; `writ_file` is repaired to `write_file`; a name with two distance-2 candidates refuses with both named.

2. SIGNATURE-HASHED PER-TOOL GUARDRAILS (HM01-C5 + OC14-C6 + OC14-C7 + OC15-C15, merged into one detector family). New module `halbert_core/halbert_core/agents/tool_guardrails.py`. A `ToolCallSignature` — SHA-256 over canonical JSON of (name, sorted-args) — replaces the tuple comparison in `_already_called` (`state_machine.py:3521-3532`). Phase 1 (the fix that matters most): PROGRESS RESET — an intervening successful mutating call (`write_file`, `write_config`, or a `run_command` that exited 0 with a write-plane verb) clears every failing signature, so edit-then-rerun is treated as a new experiment, not a replay. Maintain a `PROGRESS_RESET_TOOL_NAMES` set and a `FAILURE_TOLERANT_TOOL_NAMES` set (terminal/execute_code/run_command: failures are normal work; a same-tool streak of failures never halts by itself). Phase 2: failure classification on signatures — distinguish failing-repeat (same signature, repeated errors), no-progress (different signatures, identical result hash), identical-streak (same signature, same result) — with graduated warn/block/halt per tool and per-tool caps. Phase 3 (folded in, demoted-low per verifier): argument-churn and ping-pong detectors — churn fires only when >1 argument variant each repeats ≥3 times sharing one result hash (a novel argument RESETS liveness); warn once per decade bucket with a 256-key cap. With `max_loops=5` an uncaught churn costs at most five calls, so phase 3 is warn-tier only. Tests: failing `run_command <test>` → `write_file` edit → same `run_command <test>` is ALLOWED (the exact sequence `_already_called` refuses today); three identical failing calls on a non-tolerant tool blocks; churn warning fires on the decade bucket.

3. PER-RUN TOOL-CALL CEILING ON THE INTERACTIVE PATH (OC14-C20). Add a per-turn call cap captured at turn construction on `ExecutionContext`/turn ctx (not borrowed from a later turn — capture at `stamp()` time), checked at the last synchronous dispatch boundary before `executor.execute`. A model returning more calls than the cap is cut with a structured refusal observation ("tool budget N exhausted for this turn"). Note the interaction: SP-3 fixes `state_machine.py:3426` taking only `tool_calls[0]`; TT-05's ceiling assumes the multi-call loop exists — coordinate with SP-3 (see exclusions). Test: a model returning 40 calls in one message is cut at the cap with the structured refusal; the counter is per-turn and resets on the next turn.

4. DETACH-NOT-CANCEL (OC14-C4 + A07-G5). Build on the Wave-0 activity-clock/turn_activity dependency: `agents/turn_activity.py` already provides `stamp()`/`generation`/`claim()`. Stamp `ExecutionContext.generation` (or the tool-call record) at dispatch time; the observation writer (`ctx.add_observation` call sites that consume tool results, and the result-recording path in `_handle_executing`/`_handle_observing`) drops — and logs at info — any result whose stamped generation is stale relative to `TurnActivity.generation`. The tool keeps running (complements "yield, never kill"); its result just cannot land in the wrong turn's context. `tools/executor.py` gains an optional generation/abort parameter threaded from the dispatch site; default None keeps the script path (`script_rpc_host.py`) unchanged. Test: start a `run_command` wrapping `sleep 30`, cancel the turn mid-sleep, let the sleep finish, assert the result is logged-dropped and the next turn's context contains no trace of it. A07-G5 (a stop cannot abort an in-flight model request) rides this row only as the generation-stamp consumer — the HTTP-layer abort itself is NOT in scope (see exclusions).

5. PERSIST AN UNKNOWN-EFFECT MARKER WHEN A TURN DIES AFTER A SIDE-EFFECTING TOOL RAN (HM02-C9 + A16-G5, same row — write both facts in one change). The reboot-loop shape cannot occur (Halbert never persists structured `tool_calls`; history is plain role/content), but observations die with ctx. On the `interrupted` row written by the boot sweep / `_end_turn("interrupted")` (`state_machine.py` finally path; `conversation_sqlite.py:1722 mark_in_progress_interrupted`), persist a fixed-marker row listing side-effecting tools that had STARTED (status pending/started, using the existing classifier `tools/base.py:34 side_effects` and `tools/role_gate.py`), modelled on `_record_superseded_turn` (`state_machine.py:971-1000+`). The prompt assembler renders it as "this may have run; verify before retrying" — fixed template text, never a model summary. Same write closes A16-G5 (interrupted turn leaves a dangling question with no persisted fact). Test: kill a turn after `write_config` started, reload, assert the marker is in the next turn's assembled context.

## 8. UX rationale

No new UI surface; all user-visible effect is through the one seamless conversation as ordinary turn text and tool cards. When a malformed call is refused, the model gets a structured tool result and the user sees the turn recover (the repaired call runs, or a plain-language line in the stream that the tool call could not be understood and was not run — first person, as the computer itself: "I couldn't read that tool call's arguments, so I didn't run it" register). Guardrail halts surface as an observation the model narrates; they must never dump signature hashes or detector internals into the visible stream — the structured detail goes to logs/receipts only. The UNKNOWN-effect marker renders through the existing prompt assembler as fixed template text ("this may have run; verify before retrying") — the next turn's reply acknowledges uncertainty in measured terms ("my record of that turn is incomplete; the configuration write may have completed") rather than guessing. No emoji anywhere. No model names in any refusal or repair copy — connection-slot language only ("the connected model produced a call I couldn't parse" is wrong too — keep it about the call, not the model: "that tool call didn't parse"). Detach-not-cancel is invisible by design: the cancelled turn simply never shows the straggler's late result. Commands remain staged, never executed, and the guardrails never themselves execute anything — they only refuse, reset, or detach.

## 9. Acceptance criteria

1. A tool call whose JSON arguments are truncated is never executed and never substituted with `{}`: the turn receives a structured "arguments did not parse; resend" result, consumes no loop of the five, and `_already_called` does not treat the corrected retry as a duplicate. 2. An unknown tool name with exactly one registered name within edit distance 2 is repaired and noted; ambiguous or distance->2 names produce a structured refusal naming candidates. 3. Three consecutive iterations with no valid tool call end the turn in a graceful partial response, not a hang or a crash. 4. The edit-then-rerun sequence — failing `run_command <test>`, successful `write_file` edit, identical `run_command <test>` — is allowed (today it is refused by `_already_called` and the turn ends); three identical failing calls on a non-tolerant tool are blocked with a structured observation. 5. A model returning 40 tool calls in one message is cut at the per-turn cap with a structured refusal, and the cap counter resets on the next turn. 6. A tool cancelled mid-execution (e.g. `sleep 30`) whose result settles after the turn's generation advanced has that result dropped and logged; the next turn's context contains no trace of it. 7. Killing a turn after a `side_effects=True` tool started persists a marker that the next turn's assembled context renders as "may have run; verify before retrying." 8. All repair/refusal copy is fixed template text — deterministic, no model in the ladder, no model named, no emoji.
