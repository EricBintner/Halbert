## 1. Packet

**MP-5** — Local-model tool-call repair.

## 2. User problem

Local models that emit tool calls as prose are silently broken in Halbert today, and the turn-loop budget charges iterations dishonestly. Concretely: `_normalise_tool_calls` (halbert_core/halbert_core/model/client.py:442) reads only the structured `tool_calls` field of a provider response, and `_call_ollama` (client.py:695-766) never inspects the assistant `content` text — so when a local model answers with a prose-encoded call (e.g. `<function=read_file><parameter=path>/etc/hosts</parameter></function>`, a `[bracket]`-style call, or Harmony-syntax), the response returns with `tool_calls=[]` and the state machine falls through to RESPONDING as if the model simply answered with text. The tool call is silently lost: no error, no retry, the user gets a chatty non-answer where an action was intended. Secondarily, when arguments DO arrive as a JSON string, `_normalise_tool_calls` degrades unparseable JSON to `{}` (client.py:460-464) with only a log line — a call with trailing-comma or markdown-fenced JSON runs with empty arguments or dies downstream. Third, the iteration budget at state_machine.py:306 (`max_loops=5`, enforced at :1486) increments `loop_count` on every SEARCHING/READING/EXECUTING pass whether or not real work happened (:3858, :3950, :4226), so a turn that stalls on a no-op call burns budget the same as a productive turn, while inline thread meta-tools escape accounting entirely (bounded only by MAX_META_TOOL_REENTRIES). Fourth, a degenerate local model (over-quantised, broken sampler) can emit character-soup output that is neither an error nor a tool call — today it passes straight through to the user as the answer. The deep-eval verdict (deep-eval-group3-skills-mcp-models.md, Packet MP-5: ACCEPT) confirmed all four gaps are real, unaddressed by merged remediation (R-07 scoped to execute_code.py, R-13 scoped to utility_slot.py), and standing-rule clean: the repair is generic across whatever local model is configured (no supported-family list), garbled detection is scoped by `is_local_model()` (llm_config.py:181) not by family regex, and coercion is parsing repair, not policy.

## 3. What to build

Build four components in two files, all scoped to local models via `is_local_model()` (halbert_core/halbert_core/model/llm_config.py:181 — the one choke point; the `:cloud` tag is primary evidence, a loopback URL is not sufficient).

1. Deterministic tool-call repair extractor (the core; OC13-C3, Effort L). New module `halbert_core/halbert_core/model/tool_call_repair.py`: a streaming-tolerant parser that scans assistant text for the known prose encodings — XML-ish `<function=name><parameter=key>value</parameter></function>`, bracket-style, and Harmony-syntax — and promotes recognised calls into the exact `{id, name, arguments}` dict shape `_normalise_tool_calls` already returns (client.py:442-469), so nothing downstream changes. Hard rules, ported from openclaw packages/tool-call-repair/src/payload.ts:389 and hermes agent/message_sanitization.py:130: (a) a call is promoted only if its name is in the executor's registered tool set (the allowed-names list is passed in from `ToolExecutor.schemas`, tools/executor.py:174); (b) byte cap on the scanned text and on any single candidate payload — oversized candidates are rejected, not truncated; (c) a fenced-code tracker: any candidate that begins inside a Markdown fence (``` or indented block) is NEVER promoted — fenced examples must stay prose; the fence tracker ships with the grammar or the packet does not merge (deep-eval minimum-viable clause); (d) JSON repair for the arguments payload: strip a markdown fence wrapper, remove trailing commas, then `json.loads`; on success the repaired dict is used, on failure the candidate is dropped (never `{}`-degraded silently like client.py:460-464 — a dropped candidate is logged with the raw text and the turn continues with the remaining content). Wire-in point: `_call_ollama` (client.py:695-766) — after `content = message.get("content")`, when `tools` were offered, `tool_calls` normalised empty, and `is_local_model(model, endpoint, provider)` is true, run the extractor over `content`; promoted calls replace the empty `tool_calls` list and the promoted span is stripped from the returned `content`. Same wire-in for the OpenAI-compatible local path at client.py:540/582 (the llama.cpp/MLX/ LM Studio adapters that share the Ollama fallback or return structured-empty responses). Cloud models are never scanned — a `:cloud` slot passes content through untouched.

2. Schema-guided argument coercion (HM06-C8+C9, S). A function in the same repair module: given a promoted (or normally-parsed) call's arguments dict and the tool's declared schema (from `ToolExecutor.get_schemas()`, tools/executor.py:467, keyed by tool name), coerce string values to the declared type: `'42'`→int, `'3.14'`→float, `'true'/'false'`→bool, JSON-encoded arrays/objects parsed into containers. Only declared parameters are coerced; unknown keys pass through; a value that fails coercion is left as-is (the executor's own validation stays the final arbiter — coercion is parsing repair, not a policy decision, so the existing safety/confirmation pipeline still sees the final args). Idempotent: running it on already-correct args changes nothing. Applied inside `_normalise_tool_calls` for local models and inside the repair extractor for promoted calls.

3. Iteration budget with refunds (HM01-M6, S), in state_machine.py. Today every loop through SEARCHING/READING/EXECUTING does `self.ctx.loop_count += 1` (:3858, :3950, :4226) and the guard at :1486 fires at `loop_count >= max_loops`. Change the accounting: an iteration where the tool call was refused by the gate, errored before dispatch, or returned an empty/no-op result refunds its increment (decrement or never count), so `max_loops` charges only iterations where real work happened. Preserve two existing behaviours exactly: the AWAITING_CONFIRMATION pause at :1475-1484 stays checked BEFORE the guard; and the fall-through-to-RESPONDING (not `continue`) at :1495-1499 is kept — the comment there documents that `continue` re-fires the guard forever. Thread meta-tools keep their own separate accounting (MAX_META_TOOL_REENTRIES, :297) — they stay exempt from loop_count, this packet does not touch that seam. The loop-warning StreamEvent at :1488 keeps its current shape (session_id, loop_count, max_loops).

4. Garbled-output detection (OC22-C5, S). A heuristic in the repair module, run on assistant `content` for local models only, BEFORE the repair extractor: character-frequency / printable-ratio analysis that flags degenerate output (character soup from a broken quantised model or sampler). A flagged response raises a typed retryable error carrying reason `degenerate_output` — it does NOT pass through to the user as an answer, and it is NOT scoped by model family regex (the origin's anti-pattern); `is_local_model()` is the only gate. This item depends on MP-2's C6 for the `degenerate_output` reason taxonomy; if MP-2 has not landed, define the reason string in the repair module and let MP-2 adopt it — do not block MP-5 on MP-2.

Sequencing note from the deep-eval opportunities section: MP-5's extractor produces the `{id, name, arguments}` shape that SP-3's multi-tool dispatch loop will consume; MP-5 must land BEFORE SP-3 (otherwise SP-3's loop has nothing to loop over for prose-encoded calls). The coercion shares the dispatch choke point with R-07's execute_code hardening and lands after R-07 (already merged — no conflict today). Held out: the reasoning-effort ladder (HM03-C10) waits for a think toggle to exist.

## 4. What NOT to build

Do NOT build: (1) Any cloud-model scanning or repair — the extractor and garbled detector are gated behind `is_local_model()`; a `:cloud` slot's content passes through byte-identical. (2) Any supported-model-family list or family regex anywhere — the repair grammar is generic across encodings, never keyed to a model name; naming or matching model families on any user-facing surface violates the standing rule. (3) A third untrusted-content sanitizer — this packet parses assistant OUTPUT; it is not the SP-2/R-09 input-sanitization seam (`prompts/untrusted.py` / `mcp/metadata.py:strip_unicode_tags` own that; deep-eval cross-cutting opportunity #1 explicitly warns against a third home). (4) The multi-tool dispatch loop itself — that is SP-3 (state_machine.py:2668-2669's `tool_calls[0]` problem); MP-5 only makes prose calls visible to the existing single-call path. (5) The reasoning-effort ladder (HM03-C10) — explicitly held until a think toggle exists. (6) Any change to the thread meta-tool accounting seam (MAX_META_TOOL_REENTRIES, state_machine.py:297) or to the `_already_called` reflection logic. (7) Any change to R-07's execute_code hardening or R-13's utility slot — coercion lives in the new repair module, not in executor.py's dispatch. (8) No retry-with-different-sampler, no model re-prompting on garbled output inside this packet — detection raises a typed error; retry policy belongs to MP-2's provider-error handling / tier_router. (9) No streaming-path repair of partial tool calls arriving token-by-token — Ollama only returns tool_calls on non-streamed responses and the wire-in reads the completed `content`; incremental stream repair is out of scope. (10) No UI surface — a repaired call renders through the existing tool-card path unchanged; no new copy, no new notifications.

## 7. Effort

**L** — L (the largest single item in MP-5, and the packet's registry sizing). Justification: the extractor (item 1) is a real parser, not a regex — three grammar families (XML-ish, bracket, Harmony), a fence-state tracker that must be correct or the packet does not merge, byte caps, allowed-name validation against the live executor schema set, JSON repair with a defined drop-not-degrade failure mode, plus wire-in at three return sites in client.py (:540, :582, :764) each with its own provider shape. The reference implementations (openclaw payload.ts:389, hermes message_sanitization.py:130) are each several hundred lines for exactly this problem. Items 2-4 ride along at S each but are not free: coercion needs schema lookup plumbing from ToolExecutor into client.py's normalisation layer (which today receives raw lists, not executor state), the budget refund touches the three loop-increment sites plus the guard semantics at :1486 with two documented behaviours that must be preserved exactly, and garbled detection needs a calibrated threshold with fixtures. Test surface is proportionally large: extractor golden tests across the three grammars plus fence-trap cases, coercion idempotency, refund accounting, garbled flagging, and a regression test that cloud responses pass through unscanned. Effort L is justified because the deep-eval verdict states the extractor is the core — without it none of the other items matter — and it is the single highest-leverage repair for local-model viability: today these calls are silently lost, which reads to the user as Halbert ignoring requests for action.

## 8. UX rationale

The user-facing change is that Halbert stops silently ignoring action requests when the configured local connection slot speaks tool calls in prose. Today: user asks "read /etc/hosts", a local model emits `<function=read_file>...`, the call is lost, and the user gets a chatty paragraph instead of the file — it reads as Halbert refusing or misunderstanding. After: the call promotes into the normal pipeline, so the existing tool card appears (staged, never executed — unchanged), the confirmation flow is unchanged, and the result comes back as it does for cloud slots. Nothing new is rendered: repaired calls ride the existing tool-card and StreamEvent paths; the repair is invisible by design. If a candidate can't be repaired, the turn degrades to the text answer exactly as today — never a new error surface for a parse miss. When garbled-output detection fires, the user sees a typed retryable error through the existing error StreamEvent path, first-person and grounded: "That response came back garbled — the local slot's output was unreadable. Worth another try." — spoken as the computer itself, naming the connection slot and the measured condition (unparseable output), never naming or recommending an AI model, never a model-family excuse. The max-loops error message at state_machine.py:1493 keeps its current text; with refunds it simply fires later and honestly — only when five real iterations happened. No emoji anywhere; no new colours (nothing renders). The mid-conversation slot-switch and utility-slot surfaces are untouched (MP-4/R-13 own those).

## 9. Acceptance criteria

1. A local-slot Ollama response whose `content` contains `<function=read_file><parameter=path>/etc/hosts</parameter></function>` and whose structured `tool_calls` is empty returns from `_call_ollama` with `tool_calls == [{"id": ..., "name": "read_file", "arguments": {"path": "/etc/hosts"}}]` (id shape per `_normalise_tool_calls` convention) and `content` with the promoted span stripped. 2. Same for one bracket-style and one Harmony-syntax fixture. 3. A candidate inside a ``` fence is NEVER promoted — the fence tracker has a dedicated test with the call as the only content inside the fence, plus a mixed case (fenced example followed by a real unfenced call: only the unfenced one promotes). 4. A candidate naming a tool NOT in `ToolExecutor.schemas` is rejected. 5. A candidate payload over the byte cap is rejected, not truncated. 6. Markdown-wrapped JSON arguments and trailing-comma JSON arguments parse to the correct dict; an unrepairable arguments payload drops the candidate with the raw text logged, and never silently becomes `{}`. 7. Coercion: a schema declaring `{"count": "integer", "flag": "boolean", "items": "array"}` coerces `{"count": "42", "flag": "true", "items": "[1,2]"}` to `{"count": 42, "flag": True, "items": [1, 2]}`; running coercion twice is a no-op; an uncoercible value passes through unchanged. 8. A mock cloud (`:cloud`-tagged) response with prose-encoded calls passes through with `tool_calls == []` and byte-identical `content` — the extractor never runs for cloud slots (asserted via the `is_local_model` gate, not a URL heuristic). 9. Budget: a turn whose iteration is refused by the gate before dispatch does not consume loop budget — after N refused iterations and one productive iteration, `loop_count` reflects only the productive one; the AWAITING_CONFIRMATION pause at :1475 still pre-empts the guard; the max-loops path still falls through to RESPONDING (no `continue` regression). 10. Garbled fixture (character-soup content from a local slot) raises the typed error with reason `degenerate_output` and never reaches the user as an answer; normal local prose (short replies, non-English text, code snippets) is NOT flagged — the false-positive fixture set passes. 11. `main`-baseline discipline: this repo's main is not green (~71 baseline failures, 38 real per REV-06) — a baseline run on the merge-base is captured before claiming the packet caused or fixed anything.
