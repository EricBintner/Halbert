## 1. Executive overview (one page, plain language)

Over one day, two mature open-source agent systems (OpenClaw, a TypeScript assistant gateway; Hermes, Nous Research's Python self-improving agent) were mined for patterns that solve problems Halbert already has — some of them live defects. The findings were then checked against every app in the ecosystem that consumes them, corrected where wrong (four replies, one material correction to the record), and turned into a dispatch-ready work program. Nothing has been built yet. This document is the decision point.

**What the program is.** Nine implementation packets on the Halbert side, each a self-contained TDD work order with verified current-state facts, test code, and hard stop conditions; a five-phase memory-engine program on the Haloysius side (already handed off, phases 1–3 authorized); four founder-gated decisions; and a slate of design-only deep passes deferred until their mechanism layers land.

**What it delivers.** Concretely: a recall-driven memory promotion signal store and (gated) a curated always-in-context core; the policy lattice plus named-gate decision records and an identity-claim ladder that the unimplemented five-axis permission design needs; scheduler crash-durability (missed-run catch-up, restart budgets, run receipts, and the monitor-hash idle-cost gate — the single best cost idea in the program); typed voice ingress, closing a verified security gap where every spoken turn currently reaches the tool gate as "admin"; redaction hardening (the variant-registry leak class, an echo guard, one redaction pipeline); a founder-gated `execute_code` script tool that collapses multi-turn tool pipelines into one call; an interrupt algebra (stop/steer/redirect) with race-proof cancellation; store hardening (darwin fsync facts, FTS fail-open, declarative schema reconciliation); and the R5 eval harness whose first committed scorecard is the evidence base for ever opening the Consolidator LLM gate. The engine program separately fixes a verified self-reinforcing feedback loop (`.access()`-on-search strengthening) and a durability hazard (every memory search rewriting the whole persona store non-atomically) — both engine-verified.

**What it costs.** Roughly: wave 1 is ten dispatches, mostly sonnet/high (one focused session each) plus three opus/high items; the whole nine-packet program is on the order of 20–30 executor sessions across three waves, plus 4–5 founder sessions (sign-offs, joint design session, spot-checks), plus the engine program (5 phases, their sessions). This is the largest single dispatch wave the repo has run; the coordination machinery (per-packet branches, pathspec commits, worktrees) is already house practice and written into every packet.

**The biggest risks.** (1) Concurrent sessions editing the same tree — the founder runs several at once, and packets 02/04 both touch `state_machine.py`; (2) the state mapping is dated 2026-09-07 and every packet embeds file:line facts that age; (3) three of the four ecosystem replies were agent-produced and not yet founder-verified, yet EN-2 (the highest-blast-radius item in the whole program) merges against their call-path claims; (4) EN-2 itself — a four-consumer semantics shift on every persona in every app, deliberate and gated but real; (5) the unmerged security branch (`worktree-sec-1-one-door`, 6 commits) whose audit corpus is untracked on main — losing that worktree loses committed history, and packet 05 operates next door to it.

**My headline judgment:** the program is well-shaped. The research is honest (every packet leads with "verified current state" and names what it refuses to lift), the reconciliation caught the one fork that mattered (A2 over A1, by three-way convergence), and the gating is in the right places. Approve wave 1 now; the two things I would do differently from the matrix are cheap: start the D-1/D-2 design passes immediately (they consume no executor capacity), and resolve the sec-branch corpus question before dispatching packet 05.

## 2. The scope, judged

**Memory (packets 01, engine program, the F-3 joint session).** Right work, right order, right size. Halbert's 01-A is deliberately small: a recording instrument, not an architecture. The engine program's ordering — provenance enum first, loop-stop as one revertible change with a recorder attached, consumers rewired in the same program, re-ingestion guard with the role-filter pinned by test *before the LLM extraction exists* — is the best-designed sequence in the whole program, and the "named consumer" rule is doing real work. One watch: 01-B and EN-6 are correctly fused into one decision (F-3), but the F-3 agenda as written (budget math, double-injection, query-time-vs-file, staging) does not yet include the session-tree question — see §5.

**Lattice / permissions (packet 02, D-3).** Right work. The guest allowlist parity pin is the correct restraint — this generalizes the mechanism without rewriting the working security surface, and `merge_policies([]) → deny+ask` with Halley's fail-closed warning folded in is exactly the posture the audit found missing. D-3 (the five-axis build) correctly waits for 02-C. No cut.

**Scheduler (packet 03).** Right work, with one correction the packet itself already makes: Halbert has no prompted heartbeat, so Phase C is a decision memo, not work — good. The monitor-hash gate (03-A4) is the highest-value-per-line item in the program, but the packet does not name which jobs it applies to: the executor must define the monitor-job set explicitly (detector_sweep et al.) rather than hash-gating the scheduler wholesale — a blanket gate would silently suppress jobs like morning_report that must fire regardless. See §4.

**Voice (packet 04).** Right work, and correctly ranked urgent: "voice turns default RoleGate to admin" is a verified, live security gap; 04-A1 being opus/high is fair given it touches live routes and the single-wired `on_voice_turn` relay. My one push-back: 04-C1 (TTS code-fallback) is genuine polish, not part of the security fix — keep it in the wave but mark it droppable under time pressure; it should never block 04-A1/B.

**Redaction (packet 05).** Right work, correctly scoped away from the sec branch's held-back items. The pre-flight check exists but treats the wrong problem as primary: the pre-flight guards file overlap, while the bigger exposure is that the entire audit corpus is untracked on main and lives in git only on the unmerged branch. That is a founder-facing disposition call (commit the corpus to main, or declare the branch its home), and it should be made *before* 05 dispatches, not discovered by an executor.

**Script execution (packet 06).** Correctly gated; the founder-sign-off requirement is doing its job. My judgment for the F-1 memo: the packet's load-bearing claim, "per-call policy preserved," is true for calls that flow through the stub — but the execution environment is the same interpreter, and a script that `import`s the tool handlers directly bypasses the stub entirely. Hermes admits this class openly (scripts shelling past guards). The packet's answer is Phase-B script-text gating, which is best-effort, and the founder's own posture (deterministic-first, no LLM on security paths) means that gate must be deterministic. F-1 should therefore decide two things explicitly: (a) whether a non-sandboxed in-process `execute_code` with stub-level policy is acceptable for a single-user local assistant (I lean yes, honestly documented), and (b) whether read-only default stubs suffice for v1 with write-plane stubs deferred behind the lattice (the packet already says this — ratify it). Do not let the sign-off devolve into "the packet looks complete."

**Interrupt algebra (packet 07).** Right work, right humility — Phase B is verify-first because Halbert's abort paths are unmapped, and that is stated rather than assumed. Phase A pure mechanics dispatching now is exactly correct.

**Store hardening (packet 08).** Right work, smallest blast radius, and strategically placed: it is the foundation D-1's session tree stands on. The folded-in scheduler-JSON atomic-write task (BM/03 feedback) belongs here or in 03-B1; either is fine, but pick one owner at dispatch so it doesn't land twice.

**Evals (packet 09).** Right work and the right posture ("harness as the permanent gate", ceiling arm first, LLM arm printed SKIPPED-GATE-CLOSED). 09-B's collect-don't-trust discipline (the "38 red seams" is a historical number; the executor counts today) is exactly right. 09-B is also the packet most likely to balloon — the registry self-check is the discipline that prevents it.

**The engine program.** Approve as handed off. EN-2 is the single highest-blast-radius change in the program and the gating is proportional: consumer notice + recorded call-path confirmations before merge, one revertible commit, before/after persona dynamics documented in the handoff rather than only in the diff.

**Contradictions found (flagging, not silently resolving):**

1. **EN-4's gate is stated two different ways.** The Haloysius handoff's status line says "Phase 4 requires the founder's Option-C ratification," but (a) the matrix gates EN-4 only on "after EN-2," (b) R-EN-4's ordering puts the re-ingestion guard before Option B and ties no founder ratification to it, and (c) the handoff's own Phase 4 checklist carries no such gate. I judge the status line a drafting slip: **EN-4 is gated on EN-2, not on Option C.** The founder should confirm this reading once; engine sessions will otherwise park a safety-relevant guard behind an unrelated decision.
2. **03-B dispatch state.** The reconciliation's §5 reads "dispatch-ready: 03-A/B(+addendum)" while the matrix (§2 and §8) puts 03-B after 03-A merges. The matrix is right (B wires A's modules into `AutonomousExecutor`); the reconciliation row is stale shorthand. Same shading in the master plan's "fully independent — dispatch in parallel" line. Harmless if dispatch follows the matrix; worth a one-line reconciliation erratum.
3. **Tier mismatch, minor.** Packet 04 calls Phase A "medium scope, well-specified" while the matrix prices 04-A1 opus/high. The matrix is the authority; executors should not talk themselves down a tier from the packet prose.

**Consumer-side residues and the "recorded candidates."** Correctly excluded from this program and correctly recorded with lift conditions (two-instance rule honored). No change.

## 4. Expanded implementation plans for the first wave

**01-A — promotion signal store (sonnet/high).** Lands as: new module `halbert_core/halbert_core/continuity/promotion.py` (`PromotionSignals`, `PromotionStore`, `rank_candidates`) with SQLite persistence, wired at the two live recall sites — the thread auto-recall in `begin_turn` (threads.py:353-359) and the `recall_memory` tool (tools/recall_memory.py). Keying is `(subject, predicate)` ledger-shaped (claim-shaped, per the alignment rule with the engine). Done when: recall events record count/query-diversity/day-spread, recording is provably fail-soft (a read-only store cannot fail a turn), and the recall-echo loop is closed (`provenance="recalled_content"` produces no signals). Top risk: the two recall sites return different shapes (receipts vs ledger rows) — the key must be derivable from both or one site stays unwired and says so. **Must NOT:** touch Haloysius/memory_v2, build any injection path, or use an LLM anywhere.

**02-A/B — lattice + admission records + claims ladder (sonnet/high).** Lands as: `persona/policy.py` (SecurityLevel×AskPolicy, min/max merge, fail-closed on empty), `persona/admission.py` (decision records, decisive gate, closed reason-code set), `persona/claims.py` (strength ladder with DebateHaus composition rules written into the contract), plus the parity pin proving the lattice reproduces today's guest allowlist verdicts exactly. Done when: `merge_policies([])` is deny+ask, deny can never be loosened upward, and the parity test pins every guest tool classification. Top risk: scope creep into restructuring the working allowlist. **Must NOT:** add name tiers, touch `resolve_entity_name()`, or introduce any "no approvers → allow" shape anywhere.

**03-A incl. A4 — scheduler durability modules (sonnet/high).** Lands as three pure modules: `scheduler/catchup.py` (cadence-scaled grace — half-period clamped [120s, 2h] — fast-forward-at-dispatch, past-grace one-shots retire with a diagnostic), `scheduler/restart_budget.py` (sliding-window budget + cooldown + clock-rollback hold), `scheduler/run_receipts.py` (`started` persisted before side effects, occurrence-level idempotency, closed status set `ok/error/delivery_failed/blocked_config`, pid-alive interrupted rule), and A4's monitor-hash gate as a pure suppress/diff policy. Done when: all four modules are pure and tested, and A4 names the monitor-job set it governs in code/config — detector_sweep-class jobs, not the whole registry. Top risk: assuming the two timers (APScheduler and the thread-tick heartbeat) can be reasoned about as one; they stay uncoordinated by design in this phase. **Must NOT:** replace APScheduler, unify timers, build the heartbeat, or enable `HomeCognitiveLoop`.

**04-A1 — typed voice ingress (opus/high).** Lands as: `modality`/`speaker_*`/`claim_source` fields on the `/api/agent/message` request model (routes/agent.py:1532), relayed from `_relay_voice_turn` (app.py:1007-1036) through the frontend payload (VoiceMode.tsx:272 → useAgentStream.ts), threaded into `process()` so `speaker_role` never defaults to admin on a voice turn (state_machine.py:502), and the `build_modality_context` call site (:3151-3154) receiving audio features. Done when: a voice POST arrives recorded as modality=voice with its speaker claim; text turns byte-identical in behavior. Top risk (the packet's landmine): `on_voice_turn` has exactly one production setter — restructure the relay and spoken input silently dies with no backend test failing. **Must NOT:** change the browser-relay architecture, touch Haloysius resolver semantics, or let a biometric identification grant a role — claims record strength; enforcement is D-6.

**05-A + C2 — redaction variants + camera-gate assertion (sonnet/high).** Lands as: `ingestion/redaction_registry.py` (bounded FIFO registering raw + URL-encoded + JSON-escaped forms), registration wired at `get_config_value`'s egress-ack path, and `mcp_response()` consulting the registry — plus C2's registration-time assertion that any vision/frigate tool registration wires `camera_gate.gate_response()`. Done when: the three variant forms redact, egress-acked values register on their TTL, and an un-gated vision tool registration fails loudly. Top risk: ordering — variant redaction must run before the `EGRESS_ACK_FIELD` pass-through is honored, or the escape hatch swallows the new coverage; the registry must also be bounded enough to keep the hot `mcp_response()` path cheap. **Must NOT:** change tier routing or the EGRESS_ACK semantics, and run the pre-flight diff against `worktree-sec-1-one-door` first, recording the corpus-disposition answer.

**07-A — interrupt algebra core (sonnet/med).** Lands as: `agents/turn_activity.py` (activity generations; stale claims decline, single-shot under lock) and a pure three-verb decision core (stop/steer/redirect with demotion rules). Done when: the race test proves a stop that loses to a finishing turn declines rather than double-fires. Top risk: designing against imagined abort paths — Phase B's verify-first mapping is where reality enters; Phase A stays clean mechanics. **Must NOT:** touch the state machine, build queue machinery beyond one pending slot with replace-not-grow semantics, or copy Hermes's overlapping queue structures.

**08 — store hardening (sonnet/high, all three tasks).** Lands as: darwin PRAGMAs (`checkpoint_fullfsync=1`, forced `synchronous=FULL`) in both stores' connection factories; the FTS fail-open contract on `conversation_sqlite.py` (breadcrumb + atomic trigger-drop, LIKE continuity, refusal to reinstall triggers over an unknown gap); declarative column reconciliation parsed from the SCHEMA_SQL source on every open; and the scheduler JSON atomic-write task (single owner chosen with 03-B1 at dispatch). Done when: tests pin the PRAGMAs on darwin, a corrupted FTS never blocks a canonical write, and reconciliation is idempotent across repeated opens. Top risk: reconciliation drift — it adds columns, it must never silently downgrade or rename existing ones. **Must NOT:** adopt the WAL/repair-ladder machinery (single-process Halbert doesn't need it), touch `compact_boundaries`, or replace the `schema_version` ladder.

**09-A — the R5 harness (A1 sonnet; A2/A3 opus/high).** Lands as: extensions to the *existing* `continuity/corpus.py` (seeded synthetic threads with planted facts) and `continuity/recall_eval.py` (question bank cached by content hash, closed-book answering with forced `NOT IN CONTEXT`, programmatic judge scoring hedged guesses partial), then `eval_consolidation.py` running the arm matrix (NO_CONSOLIDATION ceiling / current deterministic / TRUNCATE_OLDEST baseline / LLM arm = SKIPPED-GATE-CLOSED) into a committed dated scorecard under `halbert_core/evals/` — **not** `docs/` (gitignored; this trap is written in the packet and bears repeating). Done when: the harness runs end-to-end with no network and no model calls, and a scorecard exists with the ceiling arm printed first. Top risk: an executor parallel-filing instead of extending corpus.py/recall_eval.py. **Must NOT:** touch the Consolidator's LLM flag, judge with an LLM where a programmatic oracle exists, or create any new provider path.

**09-B — red-seam probe battery (sonnet/high, or one ultracode batch).** Lands as: `halbert_core/probes/` — standalone scripts (no framework), one per currently-red seam, each emitting `PROBE <id>: <result>` with pass = exit 0 + marker; `PROBES.md` the table with broken-at revisions; `test_probe_registry.py` asserting the registry's claimed statuses match reality on current main. Done when: the red list is collected empirically (the "38" is historical), every seam has its probe, and the registry self-check passes. My sequencing call: **run this as one ultracode batch, early in wave 1** — its PROBES.md becomes ground truth every other packet's executor consults before blaming their change for a red test. Top risk: an executor quietly fixing a seam inside a probe (forbidden — the battery documents, repairs are separate work). **Must NOT:** debug, fix, or "make tests green"; still-red seams are recorded with their status, full stop.

**Engine EN-1 — provenance enum (sonnet/high, their session).** Lands as: `PersonaMemory.source` becomes the closed enum (`user_organic / user_echo / persona_invention / consolidation / correction / derived`), `smart_add()` extended to classify at write time, validation-on-load mapping legacy values (unknown → `derived`, logged). Done when: invalid values are rejected at the write choke point, a real legacy consumer store round-trips through the mapping, and no consumer-observable behavior changes except rejected invalid writes. Top risk: the load-time mapping exercised only against synthetic fixtures — the gate should require one real Halley/BM persona store through it. **Must NOT:** add consumer-specific branches (the engine inherits through the store) or reclassify anything on the recall path.

## 6. Risks and watch items

1. **Concurrent sessions editing the same tree.** The founder runs multiple sessions against this repo; wave 1 puts ten branches in flight, and 02/04 both touch `state_machine.py` neighborhoods. *Early warning:* merge conflicts landing on `state_machine.py`, `app.py`, `routes/agent.py`; an executor's baseline suite going red in files they never touched. *Mitigation:* per-packet branches, pathspec commits, worktrees (all already house rules); **add one thing — a wave-1 file-ownership board** (one table in the master plan status log: packet → files → session) maintained by whoever dispatches.
2. **State-mapping aging.** Every packet's "verified current state" is dated 2026-09-07; the master plan's own rule is re-verify beyond ~2 weeks. *Early warning:* a packet's step-2 "verify failure" fails in the wrong way, or a cited line number lands on different code. *Mitigation:* the rule exists; make the kickoff line non-optional for anything dispatched in October.
3. **Agent-produced replies not yet founder-verified (F-2).** Three of four replies — including the Halley/BM call-path claims EN-2's merge precondition leans on — are review-agent output. *Early warning:* any reply file:line claim that doesn't grep clean. *Mitigation:* the EN-2 precondition already requires recorded call-path confirmations; sharpen it to "recorded with greppable evidence," and run F-2 before wave 2 (§5).
4. **EN-2 blast radius.** One change alters strength dynamics for every persona of every consumer, plus removes the hottest non-atomic write. *Early warning:* consumer-side consolidation behavior shifting post-merge. *Mitigation:* already strong — one revertible commit, recorder never ships without loop-stop, documented before/after persona dynamics in the handoff. Nothing to add; do not shortcut the preconditions under schedule pressure.
5. **Sec-branch drift and the untracked audit corpus.** `worktree-sec-1-one-door` (6 commits unmerged) neighbors packet 05, and the audit corpus exists in git only on that branch — losing the worktree loses committed history. *Early warning:* 05's pre-flight diff coming back non-empty. *Mitigation:* the pre-flight exists; the corpus disposition is a founder call this week — commit the docs to main (they are documentation; low risk) or declare the branch its home explicitly.

## 7. What this program deliberately does NOT do

Confirming the boundary as specified, and in one place strengthening it:

- **No new memory architecture in Halbert beyond the packet scopes** — the curated core (01-B) is the only new injection path on the table, gated behind F-3; the ChromaDB hybrid stays fenced; no chat-UI memory surface.
- **No engine Option C until the joint session** — one decision, both repos, recorded in both.
- **No watchdog/daemon packet yet** (D-5 parked until that workstream is scheduled) — correct; OpenClaw's §8 lifts presuppose a conversation that hasn't happened.
- **No in-process subagents** — anti-pattern, stated in both reviews; packet 06 deliberately ports the mechanism and refuses the isolation shape.
- **No LLM on security paths** — redaction, tier routing, gating: deterministic everywhere; Tier 2 stays a template; the Consolidator LLM stays flag-off until 09's scorecard argues otherwise; packet 06's script-text gate must be deterministic for the same reason.
- Additions I would write into the boundary explicitly: **no fixes inside the 09-B battery** (documenting the boundary at program level, not only in the packet); **no consumer-specific branches in the engine** (already the engine program's executor note — worth restating here because wave pressure is when that rule gets bent); and **no building the prompted heartbeat** as a side effect of any scheduler work — 03-C is a founder decision, and both OSS references say liveness comes from receipts + status enum first.

The boundary is honest and complete as specified. I confirm it.
